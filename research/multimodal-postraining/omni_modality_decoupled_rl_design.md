# 실험 설계안: Omni LLM을 위한 Modality-Decoupled RL

작성일: 2026-10-27 / 상태: 초안 (선행 연구는 웹 검색 + 논문 본문 일부 확인 기준, 미검증 항목은 [검증 필요]로 표시)

## 0. 한 줄 요약
MoD-DPO의 "무관 모달리티 교란에 불변 / 관련 모달리티 교란에 민감" 원리를 **GRPO의 검증 가능한 보상**으로 옮기고, **합성 오디오-비디오 충돌 데이터**로 학습하며, RL 이후의 **모달리티 간 간섭**을 함께 정량화한다.

## 1. 배경과 공백 (선행 연구 조사 결과)

| 공백 | 근거 | 상태 |
|---|---|---|
| ① 합성 충돌 데이터로 RL | RL-CoMM은 충돌 데이터가 아니라 Music-AVQA/AVQA 일부로 학습, 평가셋 AV-ConfuseBench는 73+100문항. CogniRoute의 "conflict"는 기존 클립에 붙인 라벨 | 못 찾음 |
| ② 신뢰 모달리티 arbitration 학습 | CAD(training-free), Chain of Modality(고정 우선순위 부족 시사)만 있음 | 못 찾음 (본 설계에서는 **확장 옵션**) |
| ③ RL 후 간섭 정량화 | RL-CoMM 미측정, CogniRoute 일부(MMAU 75.4→73.2), MoD-DPO는 일반 벤치 상승. 시각 RL→오디오 저하를 직접 본 연구 없음 | 못 찾음 |
| ④ 불변/민감 정규화의 RL화 | MoD-DPO는 오프라인 DPO이며 RL 확장 논의 없음 | 못 찾음 |

"못 찾음"은 "없음"이 아니다. 착수 직전에 Semantic Scholar/Google Scholar의 "cited by"로 RL-CoMM, MoD-DPO 인용 논문을 한 번 더 확인할 것.

## 2. 가설

- **H1** 정답 보상만 쓰는 GRPO 대비, 불변/민감 보상을 추가하면 충돌·환각 벤치(AVHBench, CMM, AV-ConfuseBench 등)가 개선된다.
- **H2** 합성 충돌 데이터로 RL하면, 일반 AVQA 데이터로 RL한 것보다 충돌 상황에서의 모달리티 선택이 개선된다.
- **H3** 모달리티 특화 RL은 다른 모달리티/텍스트 능력을 저하시킬 수 있으며, 불변 보상은 이 간섭을 줄이거나(가설) 줄이지 못한다(대립가설). 두 결과 모두 보고 가치가 있다.
- **H4(비교)** (a) KL 기반 보상과 (b) 정보이득 보상은 성능과 비용 면에서 차이가 있다.

## 3. 베이스 모델과 구현

- 베이스: **Qwen2.5-Omni-7B** (RL-CoMM은 3B, MoD-DPO는 7B와 MiniCPM-O 8B이므로 7B가 직접 비교 가능)
- 알고리즘: GRPO (그룹 정규화 advantage). KL 패널티 유지 여부는 ablation으로 확인
- 프레임워크: Qwen2.5-Omni의 오디오-비디오 입력과 GRPO를 함께 지원하는 학습 스택 선택 [검증 필요]. 비동기 Omni RL 엔진 Relax(arXiv 2604.11554)는 Qwen3-Omni 기준으로 검증된 것으로 보고되어 참고 가능
- 자원: 8×80GB급 GPU 가정. 보상 계산의 추가 forward 비용은 §5에서 상대 비교만 하고, 실제 시간은 프로파일링 후 확정

## 4. 데이터 구성

### 4.1 합성 충돌 데이터 (MoD-DPO 방식 차용)
1. 오디오 캡션과 시각 캡션을 **분리해서** 생성 (시각: 캡셔너/태거, 오디오: 오디오 캡셔너). 소스 후보: MSR-VTT, VALOR32K, AudioCaps (MoD-DPO가 사용)
2. 질문마다 **관련 모달리티 태그**(audio / video / both)를 부여한다.
3. 영상 A의 비디오 + 영상 B의 오디오를 섞은 **mismatched 샘플**을 만든다 (MoD-DPO에서 성능 향상에 도움이 된 설정).
4. 질문 유형:
   - 오디오 관련: "이 소리에 X가 있는가?" → 정답은 오디오 B로만 결정
   - 비디오 관련: "이 화면에 X가 있는가?" → 정답은 비디오 A로만 결정
   - 결합: "X가 화면에 있고 소리도 나는가?" → 두 모달리티의 AND
5. 정답이 **모달리티 태그로 결정론적**이므로 판정 모델 없이 문자열 일치로 검증 가능 (CogniRoute처럼 LLM 판정기에 의존하지 않음)

### 4.2 대조군 데이터
- 일반 AVQA (Music-AVQA, AVQA): H2 비교용
- 동일 규모(예: 18K ~ 30K)로 맞춰 데이터 양 효과를 통제

### 4.3 교란(corruption) 방식
| 교란 | 용도 | 비고 |
|---|---|---|
| 확산 노이즈 (500 step) | 기본 | MoD-DPO에서 최적. 10 step은 원본과 너무 비슷해 성능 저하 |
| 다른 샘플로 교체 | 대체 | 난이도가 너무 쉬울 수 있음 |
| 오디오 mute / 비디오 프레임 마스킹 | ablation | AV-ConfuseBench 설정과 일치 |

## 5. 보상 설계

```
R = R_fmt + R_acc + λ_inv · R_inv + λ_sens · R_sens
```

- `R_fmt`: 출력 포맷 (0/1)
- `R_acc`: 정답 일치 (0/1). 태그가 정한 모달리티 기준의 정답
- `R_inv`: **무관** 모달리티를 교란했을 때 응답이 안 바뀌면 보상 (불변)
- `R_sens`: **관련** 모달리티를 교란했을 때 응답이 달라지면 보상 (민감)
- (선택) `R_lpd`: 텍스트만으로 설명되는 응답에 벌점 (MoD-DPO++의 언어 prior 패널티에 해당)

두 항은 모델을 통과한 그래디언트가 아니라 **롤아웃마다 계산되는 스칼라 보상**이다 (교란 입력의 forward는 `π_old`로 stop-gradient).

### 옵션 A: KL 기반 (분포 수준) 💬
```python
# [Option A] MoD-DPO의 KL 정규화에 가장 가까운 형태
# y: 샘플된 응답, (a, v): 원본 오디오/비디오, a': 교란 오디오, v': 교란 비디오
# 각 토큰 t에서 다음 토큰 분포를 비교
kl_inv  = mean_t KL( pi_old(. | y_<t, a,  v, x) || pi_old(. | y_<t, a', v,  x) )  # 무관 모달리티 교란
kl_sens = mean_t KL( pi_old(. | y_<t, a,  v, x) || pi_old(. | y_<t, a,  v', x) )  # 관련 모달리티 교란

R_inv  = -min(kl_inv,  kappa)         # 작을수록 좋음
R_sens = +min(kl_sens, kappa)         # 클수록 좋음. kappa로 상한(보상 해킹 방지)
```
- 장점: 원 논문(MoD-DPO)의 원리에 충실하고, 응답 전체(추론 과정 포함)의 의존성을 반영한다.
- 단점: 토큰마다 vocab 전체 분포가 필요해 메모리와 연산이 크다(완화: top-k 분포로 근사). 응답이 길수록 비용이 늘고, 길이에 따라 값이 달라져 정규화가 필요하다.
- 위험: `R_sens`는 상한이 없으면 모델이 일부러 교란에 크게 반응하는 이상한 분포를 만들도록 유도될 수 있다(kappa와 λ 민감).

### 옵션 B: 정보이득 기반 (정답 확률 수준) 💬
```python
# [Option B] 앞서 논의한 "이미지 기여도 = 정보이득" 보상의 Omni 버전
# y*: 응답에서 추출한 최종 답 토큰 (추론 부분 제외)
gain_sens = log p(y* | a, v,  x) - log p(y* | a, v', x)    # 관련 모달리티가 답에 기여한 정도
drift_inv = | log p(y* | a, v, x) - log p(y* | a', v, x) | # 무관 모달리티 교란에 의한 변화

R_sens = clip(gain_sens, 0, kappa)
R_inv  = -clip(drift_inv, 0, kappa)
```
- 장점: 답 토큰에 대한 스칼라 로그확률만 필요해 **저렴**하고 구현이 단순하다. 보상의 의미가 해석하기 쉽다("이 모달리티가 정답 확률을 얼마나 올렸나").
- 단점: 추론 과정(CoT)에서의 의존성은 보지 않는다. 모델이 이미 매우 확신하면 이득이 포화돼 신호가 약해진다. 짧은 답 위주의 질문에만 적합하다.
- 위험: 오답 응답에서는 `R_sens`가 "틀린 답에 대한 이득"이 되어 의미가 모호해진다 → `R_acc`가 1일 때만 `R_sens`를 활성화하는 게이팅을 기본으로 한다(ablation 대상).

### 두 옵션 비교 💬
| | A (KL) | B (정보이득) |
|---|---|---|
| 충실도 | 높음 (MoD-DPO 원리) | 중간 |
| 비용 | 높음 (분포 전체) | 낮음 (답 토큰만) |
| CoT 반영 | 예 | 아니오 |
| 해석성 | 낮음 | 높음 |
| 권장 용도 | 최종 성능 상한 확인 | **기본 실험(권장 시작점)** |

권장 순서: B로 가설 H1~H3을 먼저 검증한 뒤, 효과가 있으면 A로 상한과 비용 차이(H4)를 측정한다.

### 보상 해킹 점검 항목
- 응답을 비정상적으로 길게/짧게 하여 KL이나 이득을 조작하는지
- 교란을 "탐지"하는 방식으로 우회하는지 (예: 노이즈 패턴을 알아보고 응답 분포를 바꿈) → 교란 방식을 학습마다 섞어 대응
- `λ` 값에 따라 정답률이 하락하는지 (MoD-DPO도 β_inv, γ_LPD에 민감하다고 보고)

## 6. 실험 계획

### 6.1 비교군

### 6.2 Ablation
1. `R_inv`만 / `R_sens`만 / 둘 다
2. 옵션 A vs B (H4)
3. 교란 종류: 노이즈 500 step vs 10 step vs 교체 vs mute
4. 합성 충돌 vs 일반 AVQA 데이터, 그리고 혼합 비율
5. `λ_inv`, `λ_sens`, `kappa` 스윕
6. `R_lpd` 유무, KL 패널티 유무
7. `R_sens` 게이팅 유무 (옵션 B)

### 6.3 평가

|---|---|---|

### 6.4 새 지표: Modality Reliance Index (MRI)
```
MRI_rel = acc(원본) - acc(관련 모달리티 교란)    # 클수록 관련 모달리티를 실제로 사용
MRI_irr = acc(원본) - acc(무관 모달리티 교란)    # 작을수록 무관 모달리티에 강건
```
기법 적용 전후의 MRI 변화와 환각 벤치 점수의 상관을 분석한다(앞서 논의한 "visual reliance 지표"의 Omni 확장).

### 6.5 통계
- RL은 분산이 크므로 **3 seeds** 이상, 평균±표준편차 보고
- AV-ConfuseBench는 173문항으로 작으므로 신뢰구간 병기, 단독 결론 금지

## 8. 확장 옵션 (②: Arbitration / 관계 서술)
첫 논문의 핵심이 아니라 후속 또는 부록으로 둔다.
- 충돌 시 "화면과 소리가 일치하지 않는다"를 명시하는 응답, 또는 abstain에 보상 (CogniRoute의 관계 보상, OMD-Bench의 calibrated abstention 참고)
- 어려움: "어느 쪽이 정답인가"가 맥락 의존이라 라벨 정의가 모호 → 질문이 모달리티를 지정하는 경우만 먼저 다룬다.
