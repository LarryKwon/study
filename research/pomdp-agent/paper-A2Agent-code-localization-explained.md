## 0. 한눈에 보기

**한 줄 요약:** 이슈를 보고 고쳐야 할 코드 위치를 찾는 tool 기반 에이전트를 RL로 학습할 때, (1) 궤적 끝에서만 주는 보상으로는 어떤 행동이 좋았는지 구분할 수 없고 (2) 에이전트가 정답 코드를 보고도 최종 답에 넣지 않는 문제가 있다. 저자들은 **매 turn의 "발견" 보상 + 최종 "확정" 보상**, 그리고 **같은 탐색 맥락을 공유하는 turn끼리 비교하는 행동 단위 advantage**로 이를 해결한다.

**핵심 수치**

| 항목 | 값 |
|---|---|
| SWE-Bench Verified 평균 F1 | 기존 최고(CodeScout-14B) 대비 **상대 +1.58%** |
| SWE-Bench Pro 평균 F1 | 기존 최고 대비 **상대 +8.55%** |
| 모델 크기 | 4B 모델이 최대 8배 큰 baseline보다 우수 |
| 하위 수리(issue resolution) | 해결률 38.07% (LocAgent 31.78%, 정답 위치를 줄 때 45.93%) |

## 1. 미리 알아야 할 개념

### 1.1 Repository-level code localization

- **정의:** GitHub 이슈(버그 보고, 기능 요청)가 주어졌을 때, 저장소 전체에서 **수정해야 할 코드 위치**를 찾는 과제.
- **세 가지 단위(granularity)**로 예측한다.
  - **File:** `sphinx/ext/autodoc/typehints.py`
  - **Module:** 클래스 또는 최상위 함수 (예: `typehints`)
  - **Function:** 함수/메서드 (예: `merge_typehints`)
- **왜 중요한가:** 자동 버그 수리는 보통 "위치 찾기 → 패치 생성" 2단계다. 이 논문의 실험에서도 정답 위치를 주면 수리 성공률이 45.93%로, 위치를 잘못 찾으면 그 뒤가 아무리 좋아도 소용없다.

### 1.2 SWE-bench 계열 데이터

| 이름 | 내용 |
|---|---|
| SWE-bench | 실제 Python 오픈소스 저장소의 이슈와 그 이슈를 해결한 실제 PR(gold patch) 쌍 |
| SWE-Bench Verified | 사람이 검증한 500개 부분집합 (사실상 표준 평가셋) |
| SWE-Bench Pro | 더 어렵고 저장소가 다양한 벤치마크. 이 논문은 266개 사용 |
| SWE-Gym | 학습용 SWE 과제 모음 |

- **Gold location:** gold patch가 수정한 파일·클래스·함수를 파싱해 정답 위치로 쓴다. 학습 시 보상 계산에 이 정답이 필요하다.

### 1.3 Tool 기반 다중 턴 에이전트

- LLM이 매 turn **tool을 호출**(행동)하고, tool의 **결과를 받아**(관측) 다음 행동을 정하는 루프(ReAct 방식).
- 이 논문에서 행동 = **tool 이름 + 인자**. 같은 tool이라도 인자가 다르면 다른 행동이다.
- 마지막에 `Finish` 행동으로 파일·모듈·함수 예측을 출력하고 종료한다.

### 1.4 MDP 정식화와 return

- 상태 $s_t$ = 이슈 $q$ + 지금까지의 (행동, 관측) 기록.
- 정책 $a_t \sim \pi_\theta(\cdot \mid s_t)$.
- **Return(누적 할인 보상):** $G_t = \sum_{k=t}^{T} \gamma^{k-t} r_k$. 이 논문은 $\gamma = 0.9$.
- 참고: 이 논문은 POMDP나 belief라는 말을 쓰지 않는다. 대신 **history 전체를 상태로 보는** 방식이다(9절에서 다시 다룬다).

### 1.5 Sparse reward와 credit assignment

- **Sparse(희소) 보상:** 궤적이 끝날 때 한 번만 점수를 주는 방식. 예: 최종 F1.
- **Credit assignment 문제:** 15번 tool을 부르고 최종 점수 0.6을 받았을 때, 15개 중 **어느 행동이 도움이 됐고 어느 행동이 낭비였는지** 알 수 없다.
- 해결 방향은 두 가지다: (1) **중간 보상**을 주거나 (2) **행동마다 다른 advantage**를 계산한다. 이 논문은 둘 다 한다.

### 1.6 Advantage와 GRPO

- **Advantage $A$:** "이 행동(궤적)이 평균보다 얼마나 좋았나". 양수면 그 행동의 확률을 높이고 음수면 낮춘다.
- **GRPO (Group Relative Policy Optimization):** 같은 문제에 대해 여러 궤적(rollout)을 뽑고, 각 궤적의 보상을 **그룹 평균과 표준편차로 정규화**해 advantage로 쓴다. 별도의 가치 함수(critic)가 필요 없다.

$$A(\tau_i) = \frac{R(\tau_i) - \text{mean}_j R(\tau_j)}{\sigma + \epsilon}$$

- **한계:** 궤적 안의 **모든 turn이 같은 advantage**를 받는다. 좋은 궤적 안의 낭비된 행동도, 나쁜 궤적 안의 좋은 행동도 구분되지 않는다.
- GSPO는 GRPO의 변형(sequence 단위 중요도 비율)으로, 이 논문의 baseline인 CodeScout이 사용한다.

### 1.7 Turn 단위 credit assignment의 기존 접근

- **재샘플링:** 특정 turn에서 여러 번 다시 굴려 그 행동의 가치를 추정. 정확하지만 **비싸다**.
- **상태 고정(state anchoring):** 서로 다른 궤적에서 **같은 환경 상태**에 도달한 turn끼리 묶어 비교. 저자들은 코드 탐색에는 이런 "싸고 명확한 상태 기준점"이 없다고 지적한다.
- 이 논문의 아이디어는 **"직전 K개 행동이 같으면 같은 상태로 본다"**는 대용(proxy)이다.

**풀어서 설명 (이해가 어려웠던 부분)**

1. **왜 같은 상태가 필요한가 (credit assignment와의 연결):**
   - **목표:** turn마다 "이 행동이 평균보다 얼마나 좋았나"(advantage)를 따로 계산하고 싶다. 궤적 전체에 한 점수를 주는 GRPO는 이게 안 된다.
   - **advantage의 정의:** $A = G_t - b(s)$. 이 행동 뒤의 결과 $G_t$에서, **그 상태에서 보통 기대되는 결과 $b(s)$**(baseline)를 뺀 값이다.
   - **문제:** $b(s)$를 어떻게 구하나? PPO는 critic 신경망으로 학습한다. critic 없이 하려면 **같은 상태에 있던 turn들의 return 평균**을 쓰면 된다. 이것이 상태 고정(state anchoring)이다.
   - **왜 공정한가:** 같은 상태에서 출발했으므로 앞선 이력의 영향이 똑같이 상쇄되고, 남는 return 차이는 **그 시점 이후의 선택** 때문이다. 상태가 다른 turn을 섞으면 차이의 원인이 행동인지 상황인지 알 수 없다.
   - **GRPO와의 대비:** GRPO는 "상태 = 이슈(처음)"로 보고 궤적 전체의 평균을 baseline으로 쓴다. 그래서 모든 turn이 같은 advantage를 받는다.

   **숫자 예시** (설명용, 논문 수치 아님): turn 3에서 rollout A, B, C가 같은 상태(방금 `merge_typehints`를 읽음)에 있다.
   
   | rollout | turn 3 행동 | turn 3 이후 return $G_3$ | 그룹 평균(0.57) 대비 |
   |---|---|---|---|
   | A | Finish(정답 제출) | 1.0 | **+** (잘함) |
   | B | 다른 파일 계속 탐색 | 0.2 | **−** |
   | C | SearchCommit | 0.5 | 약간 − |

   GRPO였다면 A의 모든 turn(쓸데없던 turn 1 포함)이 +, B의 모든 turn(훌륭했던 발견 turn 포함)이 −를 받는다. 상태 고정에서는 **"그 상태에서는 Finish가 낫다"**는 신호가 turn 3의 행동에만 들어간다.
2. **게임·웹은 쉬운 이유:** 위치나 페이지처럼 눈에 보이는 상태가 바뀌어서, 다른 rollout이 같은 상태에 오면 그냥 같다고 볼 수 있다(논문이 인용한 Feng et al. 2026의 방식).
3. **코드 탐색이 어려운 이유:** 저장소는 고정이라 "현재 위치"가 없다. 상태 = "지금까지 뭘 읽었는가" = 전체 이력이다. 그런데 turn이 깊어지면 앞선 행동 5~6개가 다른 rollout과 정확히 일치할 확률이 거의 0이라 그룹 크기가 전부 1이 되어 비교가 불가능하다. 재샘플링은 rollout 비용 때문에 부담이 크다.
4. **해법:** 전체 이력 대신 **직전 K개 행동**으로 키를 자른다. 그러면 일치하는 turn이 생긴다.

**예시** (같은 이슈, rollout 4개, turn 3의 행동을 평가. 설명용으로 만든 예시이며 논문 수치가 아님)

| rollout | turn 1                         | turn 2                        | turn 3 (평가 대상)               | 이후 결과 |
| ------- | ------------------------------ | ----------------------------- | ---------------------------- | ----- |
| A       | SearchCodeSnippet("typehints") | SearchEntity(merge_typehints) | Finish(정답)                   | 높음    |
| B       | SearchSummary("autodoc")       | SearchEntity(merge_typehints) | ViewSummary(\_\_init\_\_.py) | 낮음    |
| C       | SearchCodeSnippet("typehints") | SearchEntity(merge_typehints) | SearchCommit(...)            | 중간    |
| D       | TraverseGraph(...)             | SearchEntity(다른 함수)           | ...                          | ...   |

- **K=1** (키 = turn 2 행동): A, B, C가 한 그룹. "그 함수를 읽은 직후엔 바로 확정(A)이 낫다"는 신호가 생긴다.
- **K=2** (키 = turn 1·2): A, C만 한 그룹. B는 혼자라 이 깊이의 advantage는 0.

**트레이드오프:** K가 작으면 많이 묶이지만 거칠고(같은 키여도 실제 맥락이 다를 수 있음), K가 크면 정밀하지만 묶이는 turn이 적다. Figure 4에서 K=1은 turn의 58.7%, K=2는 23.9%만 그룹이 만들어진다. 그룹이 없는 turn은 trajectory 단위 advantage로 폴백한다.

**근사인 이유:** (a) turn 3에서 K=2는 전체 이력이라 정확하지만, turn 6에서는 마지막 2개만 보므로 그 앞에서 본 정보가 다르면 다른 상태를 같은 상태로 묶는다. 논문 근거: 같은 행동이 평균 3.29개의 서로 다른 이력에 등장하고 turn의 79.2%는 직전 행동이 다르다. (b) 같은 곳을 읽었어도 순서가 다르면 키가 달라 못 묶는다(조사자 해석). 관측을 키에 안 넣는 것은 손실이 아니다. 저장소가 고정이고 tool이 결정적이라 같은 행동열이면 같은 관측열이기 때문이다.

**POMDP 관점 (조사자 해석):** 진짜 상태는 "지금까지 알아낸 것"(belief)이고, 직전 K개 행동은 그것을 싸게 흉내 낸 대용품이다. 명시적 belief(가설 집합, 읽은 위치 목록)가 있으면 그것을 그룹 키로 써서 경로와 순서에 무관하게 "같은 것을 아는 turn"끼리 정확히 묶을 수 있다.

### 1.8 Advantage-Weighted Regression (AWR)

- Peng et al. (2019)의 방법. 정책 경사(PPO, GRPO) 대신, **advantage가 큰 행동일수록 큰 가중치로 지도학습(최대우도)**을 한다.

$$w = \exp(\beta A) \quad\Rightarrow\quad \mathcal{L} = -\,w \cdot \log \pi_\theta(a \mid s)$$

- 장점: importance ratio 보정 없이도 데이터가 약간 오래되어도(off-policy) 안정적이다. 단점: 엄밀한 정책 경사가 아니다.

### 1.9 SFT 증류와 LoRA

- **SFT 증류(rejection sampling):** 큰 teacher 모델로 궤적을 만들고 **성공한 것만 골라** 작은 모델을 지도학습. RL 전의 warm-start로 쓴다.
- **LoRA:** 전체 가중치 대신 저랭크 행렬만 학습하는 효율적 fine-tuning. 이 논문은 rank 16, alpha 16.

### 1.10 코드 검색 도구 기반 개념

- **BM25:** 키워드 빈도 기반의 고전적 검색 점수.
- **코드 의존성 그래프:** 파일·클래스·함수를 노드로, `contains`(포함), `imports`(임포트), `invokes`(호출), `inherits`(상속)를 엣지로 하는 그래프. LocAgent 계열에서 쓰는 방식이다.
- **LLM 파일 요약:** 각 파일을 LLM이 요약해 두고 의미 기반으로 검색.

### 1.11 집합 단위 F1

예측 개수가 고정되지 않으므로 이슈마다 집합으로 계산한 뒤 평균한다.

$$\text{F1} = \frac{2\,|\hat{Y} \cap Y|}{|\hat{Y}| + |Y|}$$

- 예: 정답 함수 {A, B}, 예측 {A, C, D} → 겹침 1 → F1 = 2·1 / (3+2) = 0.4.
- 너무 많이 예측하면 precision이, 너무 적게 예측하면 recall이 떨어진다.

## 2. 문제: 어떻게 발견했고 무엇을 말하나

### 2.1 두 가지 실패 유형 (Figure 1)

서론에서 **정성적 실패 사례**로 문제를 제기한다.

1. **잘못된 탐색(Wrong exploration):** 불필요한 tool 호출을 반복한다.
2. **확정 실패(Failed commitment):** 탐색 중에 **정답 코드를 실제로 봤는데** 최종 예측에 넣지 않는다.

**Figure 1의 실제 예시** (astropy 이슈: "구조화된 np.array를 NdarrayMixin으로 자동 변환하는 동작을 제거해야 한다")

| | Turn 1 | Turn N | 정답 |
|---|---|---|---|
| Case 1: 잘못된 탐색 | `TraverseGraph` → `astropy/column.py`, `Column` | `SearchEntity` → `astropy/column.py`, `convert_col` | `astropy/table.py` / `Table` / `convert` |
| Case 2: 확정 실패 | `SearchEntity` → **`astropy/table.py`, `Table`, `convert` (정답을 봄)** | `SearchEntity` → `astropy/row.py`, `Row`, `convert_row` (다른 곳으로 이동해 그쪽을 답으로 냄) | 같음 |

Case 2가 핵심이다. **첫 turn에 이미 정답을 봤는데도** 계속 탐색하다 엉뚱한 곳을 답으로 낸다. 궤적 끝의 F1만 보는 보상은 이 궤적을 "처음부터 정답 근처에 가지도 못한 궤적"과 똑같이 0점 처리한다.

### 2.2 문제 1: 희소한 궤적 단위 보상

- 기존 RL 방법은 "결과 수준의 희소 신호만 있어서 옳은 행동과 잘못된 행동을 구분하지 못한다."
- 즉 실패 유형 1(잘못된 탐색)을 학습 신호로 잡아낼 방법이 없다.

### 2.3 문제 2: Discovery–Commit 간극

- 에이전트가 정답 위치를 **발견(discovery)**했지만 최종 답으로 **확정(commit)**하지 않는 현상.
- **정의 (5.4절):** "실패한 사례 중, 탐색 중에 정답 위치를 발견했지만 최종 예측에 넣지 않은 사례의 비율".
- **정량 근거 (Figure 3, SVG에서 역산):** LocAgent 45.6%, RepoSearcher 42.6%, CoSIL 50.3%. 세 baseline 모두 40%를 넘는다(상세는 6.5절).
- 의미: 실패의 상당수가 "못 찾아서"가 아니라 **"찾고도 안 써서"**다.

### 2.4 문제를 발견한 방식에 대한 평가

- **순서:** 서론은 정성적 사례(Figure 1)로 문제를 제기하고, 정량 검증(>40%)은 실험 절의 분석에서 사후적으로 제시한다. 본격적인 사전 pilot study는 없다.
- **설계 근거가 된 데이터 통계 (4.2.2절):** 학습 데이터에서 turn의 약 79.2%는 직전 행동이 서로 다르고, 같은 행동이 평균 3.29개의 서로 다른 이력에 등장한다. 즉 **같은 행동이라도 맥락이 다양하다**. 그래서 "행동만 보고" 묶으면 맥락이 섞이므로 **직전 이력까지 포함해 묶어야 한다**는 근거로 쓴다.

## 4. Method

### 4.1 전체 구조

```
[이슈 q] → 에이전트(Qwen3-4B/8B) ⇄ 6개 tool (저장소 인덱스)
                │
                └─ Finish → (파일 집합, 모듈 집합, 함수 집합)

학습: ① SFT (teacher 궤적 증류)
      ② 반복 3회: 이슈당 8개 rollout 수집
                 → 보상 계산 (turn 발견 보상 + 최종 F1 + DC)
                 → 행동 단위 advantage (이력 그룹화 + 궤적 단위)
                 → advantage 가중 최대우도로 학습
```

### 4.2 정식화와 Tool

- 상태 $s_t = (q, a_1, o_1, \dots, a_{t-1}, o_{t-1})$, 행동 $a_t$ = tool 이름 + 인자.
- 궤적 $\tau = (q, a_1, o_1, \dots, a_T, \hat{y})$, 정답 $y = (F, M, U)$ (파일, 모듈, 함수).
- 목표: $\max_\theta \mathbb{E}_{\tau \sim \pi_\theta}[R(\tau; y)]$.

| Tool | 기능 |
|---|---|
| `SearchCodeSnippet(query)` | BM25 키워드/식별자 검색 |
| `TraverseGraph(start, depth, edges)` | 의존성 그래프에서 contains/imports/invokes/inherits 엣지를 따라 부분그래프 반환 |
| `SearchEntity(entity)` | 파일·클래스·메서드의 소스 코드 반환 |
| `SearchSummary(query)` | LLM 파일 요약에 대한 의미 검색 |
| `ViewSummary(file)` | 특정 파일의 LLM 요약 반환 |
| `SearchCommit(query)` | 커밋 이력 검색 |
| `Finish` | 최종 예측 출력 |

프롬프트는 약 5개 파일을 중요도 순으로 반환하라고 지시하고, "파일 경로만 내면 점수의 약 2/3를 잃는다"고 경고한다.

### 4.3 보상 설계

**(a) 최종 F1 보상** — 세 단위 F1의 합 (최대 3):

$$r^{\text{F1}} = \text{F1}_F + \text{F1}_M + \text{F1}_U$$

**(b) Discovery–Commit (DC) 보상** — 단위 $g$마다, **탐색 중 본 정답 중 최종 답에 넣은 비율**:

$$\text{DC}_g = \frac{|E_g \cap Y_g \cap O_g|}{|E_g \cap Y_g|}$$

- $E_g$: 탐색 중 본 위치, $Y_g$: 정답, $O_g$: 최종 예측.
- 정답을 하나라도 본 단위들 $\mathcal{I} = \{g : |E_g \cap Y_g| > 0\}$에 대해 평균. 아무 정답도 못 봤으면 0.

$$r^{\text{DC}} = \frac{1}{|\mathcal{I}|} \sum_{g \in \mathcal{I}} \text{DC}_g$$

**(c) 종료 보상:** $r_T = r^{\text{F1}} + r^{\text{DC}}$

**(d) Turn 단위 발견 보상** — 그 turn에 **처음** 발견한 정답 비율:

$$r_t = \delta^f_t + \delta^m_t + \delta^u_t$$

- 한 에피소드 동안 각 단위의 발견 보상 합은 최대 1이다. 같은 정답을 다시 봐도 보상이 없다.
- **"발견"** = tool 결과(관측)에 정답 위치가 나타난 것. 에이전트가 알아봤는지는 무관하다(그래서 "봤는데 안 넣는" 확정 실패가 생기고 DC가 보완한다). **분모는 그 단위의 정답 전체 개수**이지 관측에 나온 항목 수가 아니다(Figure 2: $\delta^f_t = |\hat F \text{ at } t|/|F|$).
- **이 보상이 필요한 이유 (논문):** 종료 보상만 있으면 (1) 실패한 궤적은 $G_t = 0$이라 정답을 중간에 봤어도 신호가 없고, (2) 할인 때문에 성공한 궤적에서도 앞 턴의 몫이 과소평가된다.

**예시**

- 정답 함수 $Y_U$ = {A, B}.
- turn 3에서 A를 처음 봄 → $\delta^u_3 = 0.5$. turn 7에서 B를 처음 봄 → $\delta^u_7 = 0.5$.
- 최종 예측 $O_U$ = {A, C} → B를 보고도 안 넣음 → $\text{DC}_U = 1/2$.
- 함수 F1 = 2·1 / (2+2) = 0.5.

→ **발견 보상은 "잘 찾기"를, DC 보상은 "찾은 걸 확정하기"를, F1은 "최종 정확도"를 각각 겨냥한다.** 발견 보상만 있으면 "많이 보기만 하는" 정책이 생길 수 있는데, DC와 F1이 이를 견제한다.

**언제 계산하나 (타임라인 예시)**

| 보상 | 시점 | 이유 |
|---|---|---|
| 발견 보상 $\delta$ | 매 턴 | 그 턴의 관측에 정답이 **처음** 나왔는지만 보면 됨 |
| F1 보상 | 마지막에 한 번 ($t=T$) | 최종 예측이 필요 |
| DC 보상 | 마지막에 한 번 ($t=T$) | 정의에 최종 예측 $O_g$가 들어감 |

예시 (설명용, 논문 수치 아님. 정답: 파일 `a.py`, 클래스 `A`, 함수 `A.foo`·`A.bar`. 최종 예측: 파일 `a.py`, 모듈 `B`, 함수 `A.foo`. $\gamma=0.9$):

| turn | 행동 | 새로 나온 정답 | $r_t$ | $G_t$ |
|---|---|---|---|---|
| 1 | SearchCodeSnippet | 파일 `a.py` (1/1) | 1.0 | 3.93 |
| 2 | SearchEntity(A) | 클래스 `A` (1/1), 함수 `A.foo` (1/2) | 1.5 | 3.26 |
| 3 | 관련 없는 파일 열람 | 없음 | 0 | 1.95 |
| 4 | Finish | – | $r^{F1}+r^{DC}=1.67+0.5=2.17$ | 2.17 |

- $G_t = r_t + \gamma G_{t+1}$를 뒤에서부터 계산한다. 마지막 보상이 할인되어 앞 턴에도 전달되므로, 아무것도 발견하지 못한 turn 3도 $G_3=1.95$를 받는다. 이 $G_t$가 행동 단위 advantage 비교의 재료다.
- **모든 보상은 rollout이 끝난 뒤 학습 때만 계산한다.** rollout 중 에이전트는 보상을 모르고, 평가·실사용 시에는 정답을 모르므로 계산하지 않는다.
- 관측에서 파일·클래스·함수를 추출해 정답과 대조하는 구체적 방법은 확인하지 못했다.

### 4.4 행동 단위 Advantage (Action-Aware Advantage)

**그룹화 키:** 직전 K개 행동

$$\phi_K(t) = \langle a_{t-K}, \dots, a_{t-1} \rangle$$

- 같은 이슈의 rollout들 안에서, 이 키가 같은 turn끼리 한 그룹 $\mathcal{G}^{(K)}_t$로 묶는다.
- **현재 행동 $a_t$는 키에서 뺀다.** 그래야 그룹 안에 "같은 맥락에서 다른 선택을 한" 대안들이 들어와 비교가 된다.

**깊이 K의 행동 advantage:**

$$\hat{A}^{(K)}_t = \frac{G_t - \text{mean}_{j \in \mathcal{G}^{(K)}_t} G_{t_j}}{\sigma_{\mathcal{G}^{(K)}_t} + \epsilon} \qquad (\text{그룹 크기 1이면 } 0)$$

**결합:** 궤적 단위 GRPO advantage를 기준점으로 함께 쓴다.

$$A_t = \omega_0 A(\tau_i) + \sum_{K=1}^{H} \omega_K \hat{A}^{(K)}_t, \qquad \sum_{K=0}^{H} \omega_K = 1$$

- $H = 2$. 깊이 가중치는 $K+1$에 비례(Table 6). $\omega_0$ 값은 본문에 명시되지 않았다.

**예시** (같은 이슈, rollout 8개, K=1)

- 직전 행동이 `SearchEntity(merge_typehints)`인 turn이 3개 있고, 각각 다음 행동이 달랐다고 하자.

| rollout | 다음 행동 $a_t$ | $G_t$ |
|---|---|---|
| 2 | `Finish(...)` | 1.2 |
| 5 | `ViewSummary(...)` | 0.4 |
| 7 | `SearchCommit(...)` | 0.5 |

- 그룹 평균 0.7 → `Finish`는 양의 advantage, 나머지 둘은 음의 advantage.
- 즉 **"그 코드를 읽은 직후라면 바로 확정하는 게 낫다"**는 신호가 해당 turn에만 정확히 들어간다. GRPO였다면 세 turn 모두 각자 속한 궤적 전체의 점수를 그대로 받았을 것이다.

**논문 Figure 2(B)의 예시** (N=8 rollout, turn 3의 advantage 계산)

- K=1: rollout 1과 8은 turn 2 행동이 같다(그림에서 같은 색). → 두 rollout의 turn 3을 한 그룹으로 묶어 $\hat{A}^{(1)}_3$ 계산.
- K=2: rollout 1과 8은 turn 1·2 행동이 모두 같다. → 더 엄격한 그룹으로 $\hat{A}^{(2)}_3$ 계산.
- 최종 $A_3$ = 궤적 단위 advantage와 $\hat{A}^{(1)}_3$, $\hat{A}^{(2)}_3$의 가중합.
- 키가 같은 다른 rollout이 없는 turn은 그 깊이에서 advantage가 0이다(궤적 단위 항만 남음).

**왜 행동 이력을 상태 대용으로 쓸 수 있나:** 저장소가 고정돼 있고 tool이 읽기 전용이며 결정적이다. 그래서 **같은 행동 이력이면 같은 관측 이력**이 되어, 이력이 실제 상태를 정확히 대표한다.

**왜 H=2인가:** K가 커질수록 같은 키를 공유하는 turn이 드물어져(그룹 크기 1 → advantage 0) 적용 범위가 줄고, 깊은 항이 노이즈를 더한다.

### 4.5 정책 최적화: Advantage 가중 최대우도

$$\tilde{A}_t = \text{clip}(A_t, -\kappa, \kappa), \qquad w_t = \text{clip}\big(\exp(\beta \tilde{A}_t),\, w_{\min},\, w_{\max}\big)$$

$$\mathcal{L}(\theta) = \mathbb{E}_{\tau \sim \mathcal{D}} \left[ \frac{1}{|V(\tau)|} \sum_{i \in V(\tau)} w_i \cdot \big(-\log \pi_\theta(y_i \mid y_{<i}, \tau_{<t_i})\big) \right]$$

- $V(\tau)$: 에이전트가 생성한 token(assistant token)만. tool 출력 token은 학습하지 않는다.
- 각 token은 자기가 속한 turn의 advantage로 가중된다.
- $\beta = 1.5$, $\kappa = 5.0$, $w \in [0.1, 3.0]$.
- **PPO/GRPO의 clipped ratio 목적함수가 아니다.** 저자들은 AWR 방식이 약간의 off-policy 차이를 importance ratio 보정 없이도 견딘다고 설명한다. 이는 "수집 후 학습"을 반복하는 구조와 잘 맞는다.
- **정리: "GRPO식 그룹 advantage + AWR식 업데이트 + ReST식 반복".**

| 단계 | 방식 | 계열 |
|---|---|---|
| rollout 수집 | 이슈당 8개를 현재 정책으로 샘플링 | GRPO와 동일 |
| advantage 계산 | 그룹 평균·표준편차로 정규화 (critic 없음) | GRPO식 |
| 정책 업데이트 | advantage 가중 최대우도 (ratio·clip ε 없음, 가중치 항상 양수) | AWR (Peng et al. 2019) |
| 반복 | 수집 → 2 epoch 학습, 최대 3회, 매번 현재 정책으로 재수집 | ReST / expert iteration (Gulcehre et al. 2023) |

- Table 6에 KL 계수나 clip ε가 없고 본문에서 KL 언급도 찾지 못했다. 정책 이탈을 직접 제한하는 장치는 없고, 가중치 상하한(0.1~3.0)이 간접적으로 억제한다.
- 실패한 rollout도 가중치 ≥0.1로 학습에 쓰인다(rejection sampling 아님).
- Table 3의 "GRPO" baseline이 같은 SFT 초기값·보상·rollout 수로 학습됐는지는 본문에서 확인하지 못했다. GRPO 대비 +5.84점은 목적함수·advantage·보상이 동시에 다른 비교일 수 있다.

### 4.6 학습 절차

1. **SFT:** teacher(Qwen3-30B-A3B-Instruct-2507) 궤적 중 **각 단위에서 정답을 하나 이상 맞힌 1,410개**로 3 epoch.
2. **RL (최대 3회 반복):** 현재 정책으로 이슈당 8개 rollout 수집 → 보상과 advantage 계산 → 2 epoch 학습.

## 6. 실험을 어떻게 진행했나

### 6.1 실험 설정

### 6.6 이력 깊이 H (Figure 4)

- **설정:** H는 결합에 쓰는 최대 깊이다(H=2면 K=1, 2 항을 모두 사용). 커버리지는 깊이 K=H에서 **크기 2 이상인 그룹에 속하는 turn의 비율**, 즉 실제로 행동 단위 신호를 받는 turn의 비율이다.
- **수치** (Qwen3-8B, Verified, SVG에서 역산):

| H | Turn 커버리지 (%) | 파일 F1 | 모듈 F1 | 함수 F1 |
|---|---|---|---|---|
| 1 | 58.7 | 72.15 | 47.15 | 40.74 |
| **2** | 23.9 | **73.31** | **47.98** | **41.01** |
| 3 | 14.5 | 72.67 | 47.17 | 39.43 |
| 4 | 12.0 | 72.25 | 44.49 | 38.11 |
| (그룹화 없음, Table 3) | – | 72.19 | 47.10 | 40.19 |

- F1은 **H=2에서 최고**이고, H가 커지면 커버리지가 줄면서 하락한다. 그림의 오른쪽 F1 축은 48~72 구간이 생략된 끊긴 축이라, 그림만 보면 차이가 실제보다 커 보인다.
- **표에서 바로 보이는 점 (조사자 분석):**
  - **H=1은 그룹화가 없는 것과 거의 같다.** 파일 72.15 vs 72.19, 모듈 47.15 vs 47.10이다. 직전 행동 하나만 같은 turn끼리 묶는 것으로는 효과가 거의 없다.
  - **이력 그룹화의 이득은 사실상 K=2 항에서 나온다.** 그런데 K=2 그룹에 속하는 turn은 **23.9%뿐**이다. 나머지 약 76%의 turn에는 K=2 신호가 없다.
  - H=4는 그룹화가 없을 때보다도 모듈·함수 F1이 낮다. 깊은 항이 노이즈를 더한다는 저자 설명과 맞는다.

### 6.7 행동 단위 advantage 분포 (Figure 5)

- 학습 데이터에서 계산한 turn별 $A_t$ (H=2): 평균 **μ = −0.006**, 표준편차 **σ = 0.404**. 0을 중심으로 뾰족하고 꼬리가 긴 분포이며, 대부분 ±1.5 안에 있다.
- 저자 해석: 이력 그룹화가 안정적이고 편향 없는 baseline을 준다.
- **실제 학습 가중치로 환산 (조사자 계산):** $w = \text{clip}(e^{1.5 A}, 0.1, 3.0)$
  - ±1σ 범위의 turn은 가중치가 **0.55~1.83**이다.
  - 상한 3.0은 A > 0.73에서, 하한 0.1은 A < −1.54에서 걸린다. advantage 자르기 기준(κ=5)은 이 분포에서는 사실상 걸리지 않는다.
  - **가중치는 항상 양수다.** 샘플된 행동은 나쁜 것이라도 직접적인 gradient는 확률을 올리는 방향이고, 같은 맥락의 좋은 행동이 더 크게 올라가면서 **상대적으로만** 줄어든다. 즉 학습은 **자기 rollout 전체를 advantage에 따라 조금씩 다르게 가중해 모방**하는 것에 가깝다. PPO/GRPO처럼 나쁜 행동의 확률을 직접 깎는 음의 gradient는 없다.

## 8. 비판적 읽기

### 강점

- 문제 정의가 명확하다. "발견했지만 확정하지 않음"을 정량화하고(>40%) 직접 겨냥한 보상을 설계했다.
- 행동 이력을 상태 대용으로 쓰는 그룹화는 **추가 rollout 비용 없이** turn 단위 credit을 준다. 결정적·읽기 전용 환경이라는 성질을 잘 활용했다.
- 작은 모델(4B)과 적당한 자원(GPU 4장, 2~3일)으로 재현 가능한 규모이고 코드를 공개했다.
- 하위 수리 실험으로 실제 효용까지 보였다.
- DC 보상의 효과가 문제 정의와 직접 맞물려 검증된다. 간극이 36.0% → 25.0%로 줄면서 F1도 오른다(Figure 3).

### 약점 / 의문점

1. **통계적 신뢰도:** greedy 1회 실행이라 분산이 없다. Verified의 절대 개선(0.84점)은 노이즈 범위일 수 있다.
2. **Baseline 비교 조건:** 일부 수치를 다른 논문에서 가져와 tool, context 한도, 예측 개수가 다르다. 특히 프롬프트가 "약 5개 파일"을 내도록 유도하는데, 이는 F1의 precision-recall 균형에 직접 영향을 준다.
3. **개선 원인 분리:** "둘 다 제거"(71.01)와 GRPO(67.47)의 차이가 핵심 기법의 기여(2.3점)보다 크다. turn 발견 보상, AWR 목적함수, 반복 수집 중 무엇이 효과를 냈는지 분리된 실험이 없다. 또한 PPO와의 직접 비교도 없다.
4. **정답 의존 보상:** turn 보상과 DC 보상 모두 학습 시 gold location이 필요하다. 정답 라벨이 없는 실제 환경으로 옮기기 어렵다.
5. **상태 대용의 적용 범위:** 행동 이력 = 상태라는 가정은 **결정적·읽기 전용** 환경에서만 성립한다. 파일 수정, 테스트 실행(비결정적), 외부 상태 변화가 있으면 같은 이력이 다른 상태를 가리킬 수 있다.
6. **세부 정보 누락:** $\omega_0$ 값, LLM 요약 생성 모델, Pro 266개 선정 기준이 명시되지 않았다.
7. **하위 수리 비교의 범위:** 가장 강한 baseline(CodeScout, RepoNavigator)이 수리 실험에서 빠져 있다.
8. **이력 그룹화의 실효 범위가 좁다 (Figure 4에서 역산):** H=1은 그룹화 없음과 거의 같고(파일 72.15 vs 72.19), 이득은 K=2 항에서 나온다. 그런데 K=2 신호를 받는 turn은 23.9%뿐이다. "행동 단위 credit"이라는 이름에 비해 실제로 행동별 신호를 받는 turn은 소수다.
9. **과포함(over-inclusion) 편향:** 모듈 단위 recall 63.42 vs precision 42.56. DC 보상은 본 정답을 넣으면 보상하지만 본 오답을 넣어도 벌하지 않는다. 그래서 commit을 늘리는 방향이 precision 하락과 함께 올 수 있다. 모듈 F1이 CodeScout-14B보다 낮은 원인으로 보인다.
10. **DC 간극 지표의 분모:** "실패 사례 중 비율"이라 방법마다 분모가 다르다. 성능이 좋아질수록 남은 실패가 어려운 사례로 바뀌므로 비율 비교만으로는 한계가 있다.
11. **폐쇄형 모델과의 격차:** OpenHands-Bash rem + Claude-Sonnet-4.5가 모듈 +19점, 함수 +21점 높다. 이 논문의 기여는 "작은 오픈 모델로 격차를 얼마나 줄였나"로 읽어야 한다.
12. **음의 gradient 부재:** advantage 가중 MLE는 가중치가 항상 양수(최소 0.1)라 나쁜 행동을 직접 억제하지 않는다. GRPO보다 좋은 결과가 이 목적함수 덕인지 보상·그룹화 덕인지 분리되지 않는다(3번과 연결).
13. **"SFT는 낯선 저장소에 적응 못 한다"는 주장의 근거가 약하다:** 근거는 (a) 이슈 1건의 사례 연구(부록 G: 검색이 빈손일 때 검색어를 넓히기만 하다 오답), (b) Table 3의 SFT-only가 전체보다 파일 F1 7.11점 낮음, 이 둘이다. (b)는 **SFT 대 SFT+RL** 비교라서 "학습 저장소에서는 괜찮고 새 저장소에서만 무너진다"를 보이지 못한다. 학습 저장소 대비 성능 실험이 없고, RL이 F1 보상을 직접 최적화한 효과와 분리되지 않는다. 사례 연구는 저자가 고른 1건의 예시다.

## 9. POMDP·belief 연구와의 연결

> 상세한 지형은 [agentic-rl-pomdp-research-landscape.md](agentic-rl-pomdp-research-landscape.md) 참고.

- **Discovery–commit 간극 = belief→행동 간극의 SWE 버전.** "Agents Explore but Ignore"(2604.17609)의 "발견하고 무시함", Strategic play 논문(2605.00226)의 "belief는 있는데 행동으로 안 이어짐"과 같은 현상을, 이 논문은 보상 설계로 직접 다룬다. → 지형 문서의 **기회 2를 SWE localization에서 부분적으로 실증**.
- **Privileged 정보를 dense 보상에 사용 = 기회 1과 겹침.** 차이는 보상 대상이다.

| | A²Agent | 기회 1 (state-anchored belief shaping) |
|---|---|---|
| 보상 대상 | 정답을 **봤는가**(관측 커버리지) + **확정했는가** | 에이전트 **belief의 질** $\log b(s^*)$ |
| 부정적 증거("여긴 아니다") | 보상 없음 | belief가 정답 쪽으로 이동하면 보상 |
| 과신·과포함 | 벌점 없음 (실제로 precision 하락이 관찰됨, 8절 9번) | 로그 점수가 벌점 부과 |
| 명시적 belief | 없음 (history = 상태) | 있음 |

- **상태 대용의 한계 = 기회 3의 출발점.** 행동 이력 그룹화가 깨지는 쓰기·비결정·동적 환경에서는 **belief 기반 그룹화**가 필요해진다(해석).
- **연구 설계상 시사점:** 기회 1을 SWE localization에서 한다면 A²Agent가 반드시 비교해야 할 baseline이다. 차별화는 (a) 수리까지 포함한 쓰기 환경, (b) 상태가 변하는 장애 진단 환경, (c) commit 정확도·보정·가설 배제 능력에서의 우위로 보여야 한다.
