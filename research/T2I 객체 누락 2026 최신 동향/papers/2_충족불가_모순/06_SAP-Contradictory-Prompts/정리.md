# Image Generation from Contextually-Contradictory Prompts
- 저자/소속: Saar Huberman, Or Patashnik, Omer Dahary, Daniel Cohen-Or (Tel Aviv University), Ron Mokady (BRIA AI)
- 발표: arXiv 2506.01929 (v2, 2026-03-23, cs.GR). CVPR 2026으로 전달받았으나 PDF 본문에는 학회 표기가 없음(확인 불가). 프로젝트 페이지: https://tdpc2025.github.io/SAP/
- 링크: https://arxiv.org/abs/2506.01929
- 읽은 범위: 본문 전체 + Supplementary(LLM instruction 전문, in-context 예시, ContraBench/Whoops-Hard 프롬프트 전체 목록, VLM 평가 프롬프트, failure 분석) 모두 읽음
- 한 줄 요약: 모델의 사전분포(prior)가 한 개념에 다른 개념을 묶어(entangle) 두기 때문에 생기는 "맥락적 모순(contextual contradiction)"을, LLM이 만든 **단계별 proxy prompt**를 denoising 구간마다 바꿔 넣는 방식(SAP: Stage-Aware Prompting)으로 학습 없이 해소한다. 초기 단계에서는 레이아웃이 모순 없이 잡히도록 대체 개념을 쓰고, 뒤에서 원래 개념으로 바꾼다.

## 1) 미리 알아야 할 기본 개념

- **Coarse-to-fine denoising**: diffusion/flow 모델은 초기 step에서 저주파 구조(장면 레이아웃, 큰 색 영역)를, 중간에서 형태·자세·위치를, 후반에서 정체성·재질·세부 디테일을 결정한다(eDiff-I, Attend-and-Excite, Patashnik et al. 2023 등). SAP는 여기서 두 가지 관찰을 끌어낸다. (i) **Irreversibility of details**: 한번 정해진 레이아웃·형태는 나중에 프롬프트가 바뀌어도 바뀌지 않는다. (ii) **Flexibility in high-frequency details**: 초기에는 고주파 디테일이 아직 없으므로 프롬프트가 무엇이든 디테일에 영향을 주지 않는다.
- **x0-prediction 시각화**: 각 step에서 모델이 예측한 "최종 깨끗한 이미지(x̂0)"를 보면, 어느 시점에 무엇이 확정되는지 알 수 있다(Fig. 4).
- **Entangled concept(얽힌 개념)**: 학습 데이터의 동시출현 편향 때문에 단어 하나가 언급되지 않은 맥락까지 끌고 오는 현상. 예: "duck" → 물, "polar bear" → 눈, "howling" → 달, "dragon" → 불. 저자들은 cross-attention map에서 토큰이 객체 영역뿐 아니라 연관 맥락 영역(달, 불꽃)에도 attend하는 것을 보여준다(Fig. 3a). **요청하지 않은 객체(unrequested object)가 생기는 메커니즘**과 바로 연결된다.
- **Contextual contradiction(맥락적 모순, 논문 고유 정의)**: 모델 prior가 A를 C와 얽어 두었고 B가 C와 모순이면, "A가 B와 맥락적으로 모순"이라고 정의한다. 예: butterfly↔flowers인데 bee's hive와 충돌, Disneyland↔행복인데 crying과 충돌. "웃으면서 찡그린다" 같은 **직접 모순(direct contradiction)** 과는 구분된다(Fig. 2). 즉 원리상 충족할 수 있는(satisfiable) 요구를 다룬다.
- **Cross-attention map / log-ratio map**: 텍스트 토큰별로 이미지 공간 중 어디에 영향을 주는지 보여준다. "a woman writing with a dart"에서는 'writing'과 'dart'가 같은 영역(손/도구)을 두고 경쟁하고 'writing'이 이긴다(Fig. 3b). 그래서 dart는 pen으로 대체되는데, 이는 **요구 객체가 prior 객체로 치환되는 누락**이다.
- **Prompt switching / proxy prompt**: denoising 도중 conditioning 프롬프트를 바꾸는 기법이다. Prompt-to-Prompt, MagicMix, P+, R2F 등이 있다. SAP의 proxy prompt는 "그 단계에서 형성되는 속성은 원래 의도대로 유지하되 모순은 없는" 임시 프롬프트다.
- **R2F (Rare-to-Frequent, Park et al. 2024)**: LLM이 희귀 개념에 대응하는 빈번 개념을 찾아 주고, 정해진 timestep마다 rare/frequent 프롬프트를 번갈아 넣어 rare concept 생성을 돕는 training-free 기법. SAP의 가장 직접적인 비교 대상이다. 저자들은 R2F가 단계와 의미 속성을 맞추지 않아 두 개념이 섞인 **hybrid**를 자주 만든다고 비판한다.
- **기타 베이스라인**: **Annealing Guidance**는 step별 CFG scale을 작은 MLP로 예측한다. **ELLA**는 SD1.5에 LLM 인코더를 결합해 fine-tune한 모델이다. **VL-DNP**는 VLM이 생성 중간에 동적으로 negative prompt를 만든다.
- **Whoops! (Bitton-Guetta et al., ICCV'23)**: 함께 나오는 두 요소를 쓴 뒤 하나를 덜 어울리는 대안으로 바꿔 만든, 상식을 깨는 500개 프롬프트 데이터셋.
- **평가 지표**: GPT-4o가 1–5점으로 prompt alignment를 매기고, 3개 seed 평균을 20–100으로 스케일한다(Table 13 프롬프트). 사용자 연구는 쌍대 비교 win rate다.

## 2) 무엇을 문제로 보았나 (관찰한 증상 · 분석한 원인)

**관찰한 증상**
- 그럴듯하지만 통계적으로 드문 조합에서 모델이 한쪽 개념을 무시하거나 왜곡한다. "A butterfly is in a bee's hive" → 꽃 위의 나비. "A dragon blowing water" → 불을 뿜음. "A woman writing with a dart" → 펜으로 씀. "howling wolf and flying bat at midday" → 초기 step부터 밤과 달이 박혀 "midday"가 무시됨(Fig. 4).
- 스타일 충돌도 있다. "photorealistic SpongeBob"처럼 비현실적 내용이 들어가면 FLUX는 사실적 사진을 요청해도 cartoon으로 기본 회귀한다(Fig. 11). 저자들은 이것도 fantastical content ↔ realistic style의 맥락적 모순으로 해석한다.
- 정량적으로, FLUX-dev의 GPT-4o alignment는 Whoops 78.85 / Whoops-Hard 44.3 / ContraBench 57.16에 그친다(Table 1).

**원인 분석 (저자 가설과 근거)**
1. **Entanglement**: 토큰이 연관 맥락까지 attend한다(Fig. 3a의 attention map, 정성적 근거).
2. **Attention 경쟁**: 모순되는 두 토큰이 같은 공간 영역을 두고 경쟁하고, prior가 강한 쪽이 지배한다(Fig. 3b의 log-ratio map, 정성적 근거). 요구된 개념이 attention 경쟁에서 져서 사라지는 메커니즘이며, DominanceBench의 DvD와 같은 계열의 관찰이다.
3. **Irreversibility**: 얽힌 맥락(밤, 달, 꽃)이 초기 step에 레이아웃으로 확정되면 뒤에서 되돌릴 수 없다(Fig. 4의 x0 예측 근거).
4. **Placeholder가 없으면 누락된다**: 충돌 개념을 초기에 빼고 나중에 넣으면 그 객체가 너무 작아지거나 아예 **누락**된다. 레이아웃에 "자리(slot)"가 없기 때문이다(Fig. 6: snowman을 step 1/3/5에 넣으면 점점 작아짐). 또 proxy가 구조적으로 부적합하면(rat은 날지 않음) 날개 달린 앉은 늑대처럼 최종 객체가 틀어진다(Fig. 4 우상단).
   → 내 연구에서 가장 중요한 관찰이다. **객체가 레이아웃 형성 단계에서 자리를 확보하지 못하면 이후 프롬프트로는 복구하기 어렵다**는 실증 근거다.

## 3) 방법 (Method)

**핵심 아이디어**: 원래 프롬프트 P를 proxy prompt 수열 {p1..pn}과 timestep 구간 {I1..In}으로 분해한다. 각 pi는 (i) 해당 구간에서 형성되는 속성(레이아웃, 형태, 정체성, 디테일)은 P와 같게 두고, (ii) 그 단계에서 생길 모순은 피한다. 마지막 proxy는 항상 원래 프롬프트다.

**알고리즘 단계**
1. **Prompt decomposition (LLM, GPT-4o)**: system prompt(Table 8), 수작업 in-context 예시 20개, 짧은 explanation 생성 요구를 함께 준다. 출력은 `prompts_list`(최대 3개)와 `switch_prompts_steps`다.
   - LLM에게 준 단계 가이드(50-step FLUX 기준, Table 8): step 0–2 장면 레이아웃·지배 색, 3–6 객체 형태·크기·자세·위치, 7–10 정체성·재질, 11–13+ 세부 디테일.
   - **Concept substitution 전략**: 형태·크기·시각적 기능이 비슷한 대체물을 먼저 쓴다. 예: lion handstand → "a man doing a handstand"(1–4) → "a man in a lion costume"(5–6) → "a lion doing a handstand"(7–50) (Fig. 5). dragon blowing water → "white smoke"(~3) → water. coin floats → "leaf floats"(~4) → coin. boxer split → gymnast → boxer → professional boxer.
   - 대체물이 없으면 배경만 먼저 그린다. 예: polar bear in desert → "A desert"(~2) → 전체 프롬프트.
   - 시각적으로 일관된 프롬프트는 분해하지 않는다. in-context 예시에 non-contradictory 사례가 하나만 있어도 LLM이 full prompt를 그대로 쓰는 쪽으로 기본 동작한다고 보고한다.
2. **Stage-aware prompt injection**: step t에서 t ∈ Ii인 pi로 conditioning한다. 아키텍처 변경이 없고 아무 pretrained 모델에나 붙는다.

**비용·학습**: 학습이 필요 없다. 프롬프트당 LLM 호출 1회와 추가 텍스트 임베딩 몇 번이 전부라 생성 시간 증가는 미미하다고 주장한다(정량 수치는 제시하지 않음). 기본 설정은 FLUX.1-dev, T=50, proxy 최대 3개이고, SD3.0에는 같은 proxy와 구간을 그대로 이식했다.

**새 벤치마크**
- **Whoops-Hard**: Whoops! 500개 중 어려운 100개를 큐레이션(Table 12에 전체 목록). 선정 기준은 "particularly difficult"라고만 되어 있고 정량 기준은 없다.
- **ContraBench**: 40개 프롬프트(Table 11). ChatGPT가 맥락적 모순 정의에 따라 후보를 만들고, 사람이 명확한 모순만 남기는 필터링을 거쳤다.

## 5) Challenge를 걸 부분

**(a) 평가 설계의 약점 — 내 비판**
- **표본이 작다**: ContraBench 40개 × 3 seed = 120장, Whoops-Hard 100개다. 점수 차 몇 점의 신뢰구간이나 유의성 검정이 없다. user study도 24개 프롬프트에 그친다.
- **Whoops-Hard 선정 편향**: "어려운 100개"의 정의가 없다. FLUX/SD3가 실패한 프롬프트를 골랐다면 baseline은 구조적으로 낮게 나오고 재생성만 해도 평균으로의 회귀 효과가 난다. 그런데 baseline 재생성 점수는 보고되지 않는다.
- **Train/test 누설 가능성**: in-context 예시 20개는 "FLUX에서 실패하는 맥락적 모순 프롬프트를 수동 분해"해서 만들었는데 전체 목록이 공개되지 않았다. Table 10의 분해 예시("Shrek is blue", "A dragon blowing water", "A grown man has a baby's pacifier", "A professional boxer does a split")는 Whoops-Hard/ContraBench 프롬프트와 겹친다. Table 10이 in-context 예시인지 출력 예시인지 불분명하다는 점은 리뷰 질문거리다.
- **판정자 편향**: 단일 VLM(GPT-4o)의 1–5 홀리스틱 점수만 쓴다. 분해(proxy 생성)도 GPT-4o가 한다. 같은 모델 계열이 "의도된 의미"를 정의하고 채점까지 하므로 해석이 맞물릴 수 있다. 객체 존재 여부를 분리한 지표(VQAScore, 객체별 yes/no, detector 기반 누락률)가 없어서 **"어떤 개념이 누락됐는가"를 따로 볼 수 없다**.
- **R2F_FLUX 재구현 점수(25–49)가 비정상적으로 낮다**: base FLUX(57.16)보다도 훨씬 낮다. 구현이나 하이퍼파라미터 문제일 가능성이 크고, 이 수치가 "R2F < SAP" 인상을 키운다. 공정한 비교는 원 R2F(SD3) vs SAP_SD3 정도이고, Whoops에서 그 차이는 2.4점이다.

**(b) 가정과 일반화의 약점**
- **step 구간이 특정 스케줄러와 step 수에 하드코딩**되어 있다(FLUX-dev 50 step 기준 "0–2/3–6/7–10/11–13"). 같은 구간을 SD3에 그대로 썼다는 것은 반대로 모델별 최적화가 안 됐다는 뜻이기도 하다. 4–8 step distilled 모델(FLUX-schnell, SDXL-Turbo)이나 AR/unified 모델(BAGEL, Janus 등 CF-World에서 평가된 계열)에는 바로 적용할 수 없다. 유효 범위가 약 12 step뿐이라 timestep shift나 sampler가 달라지면 민감할 가능성이 있다.
- **2-개념 짧은 프롬프트만 다룬다.** proxy는 최대 3개다. 긴(dense) 프롬프트에 모순이 여러 개 있거나 객체가 10개 이상인 장면은 다루지 않고, 한 객체에 쓴 proxy가 다른 객체 배치에 주는 부작용도 측정하지 않았다.
- **Satisfiable 모순만 다룬다.** 해결 가능한 모순을 "어떻게든 둘 다 만족"시키는 방법이라, 원리상 충족이 불가능한 요구(direct contradiction)나 우선순위 결정이 필요한 상충 요구에서 모델이 **무엇을 선택하는지**는 다루지 않는다.
- **Proxy 잔여물(unrequested object)을 측정하지 않았다.** "man in lion costume" 같은 proxy가 남겨 놓는 의상 질감, 사람 비율 같은 흔적이 최종 이미지에 요청하지 않은 요소로 남을 수 있는데 측정하지 않았다. 마찬가지로 entanglement가 끌고 오는 맥락 객체(달, 꽃)가 SAP 후 실제로 줄었는지도 정량화하지 않았다.
- **원인 분석이 정성적이다.** Fig. 3 attention map 몇 장이 전부다. "attention 경쟁에서 진 쪽이 사라진다"는 가설을 대규모로 검증하지 않았다(DominanceBench가 SD1.x에서 정량화한 것과 대조적).
- 실패의 63%가 LLM의 proxy 선택에서 나온다. 방법이 결국 LLM의 시각적 상식에 의존한다.

**(c) 내 관심사로의 확장 — 후속 연구 아이디어**
1. **긴 프롬프트 속 모순 해소 행동 분류 벤치마크**: ContraBench/Whoops-Hard의 모순 쌍(A, B)을 10–30개 객체가 나오는 dense prompt 안에 넣고 (i) 위치(앞/중간/끝), (ii) A–B 간 거리(토큰 수), (iii) 주변 객체 수를 조작한다. 결과를 **해소 행동**으로 분류한다: A만 / B만 / hybrid(R2F형) / 둘 다 누락 / 제3안(prior 객체로 치환, 예: dart→pen) / **주변 무관 객체 동반 누락(collateral omission)**. 모순 하나가 다른 객체의 누락률을 높이는지가 핵심 질문이다. 판정은 객체별 VQA + open-vocabulary detector로 분리 측정한다.
2. **"Slot reservation" proxy로 긴 프롬프트 누락 완화**: SAP의 Fig. 6 관찰(초기 자리가 없으면 작아지거나 누락됨)을 일반화한다. 긴 프롬프트의 모든 객체에 대해 초기 1–4 step에는 형태가 비슷한 generic placeholder("a small round object", "a person-sized figure")를 넣어 자리를 먼저 확보하고, 이후 원래 객체로 바꾼다. 객체 수 K에 따른 누락률 곡선을 baseline, Attend-and-Excite 계열, SAP와 비교한다. LLM 없이 객체 카테고리별 shape prior 사전만으로 가능한지도 본다.
3. **LLM-free 적응형 스위칭 시점**: 하드코딩된 step 대신 x̂0나 attention이 수렴하는 시점(예: DominanceBench의 focus score, 레이아웃 마스크 IoU 안정화)을 감지해 스위칭 시점을 자동으로 정한다. distilled·flow·AR 모델로 옮겨 일반화 실험을 한다.
4. **Proxy·entanglement 잔여물 = 요청 외 객체 측정**: SAP 전후로 "요청하지 않은 객체" 수를 detector로 센다. 예: howling→moon, duck→물, proxy 의상 흔적. "모순 해소가 요청 외 객체를 줄이는가, 아니면 다른 종류로 바꾸는가"를 정량화하는 지표(예: unrequested-object rate)를 제안한다.
5. **승패 예측기**: 두 개념 중 어느 쪽이 이길지를 생성 전(text-embedding 유사도, 개념별 seed 다양성, 첫 step attention log-ratio)에 예측하는 모델을 만들고, 예측이 맞을 때만 SAP를 적용하는 gating으로 비용과 부작용을 줄인다.
