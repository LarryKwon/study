# GenOlympiad: Benchmarking Frontier Image Models at Their Capability Boundaries
- 저자/소속: Xi Hu (Australian National University), Martin Bell (Canva), Liang Zheng* (Australian National University, corresponding)
- 발표: arXiv preprint (cs.CV), 2026-10-19. 문서 헤더가 "Preprint"(ICLR 스타일 템플릿)이고 30쪽이다. 투고처는 명시하지 않았다.
- 링크: https://arxiv.org/abs/2610.26850 · 코드 https://github.com/GenOlympiad/GenOlympiad · 프로젝트 https://genolympiad.github.io/
- 읽은 범위: 본문 전체 + 부록 A.1–A.4(프롬프트 길이, 재실행 안정성, 축 상관, 혼동행렬, 구축 프로토콜, positive/negative 예시 프롬프트, 에이전트 지시문, coding model system prompt). 그림 17(예시 이미지)은 텍스트 추출이 깨져 내용 확인 불가.
- 한 줄 요약: 9개 능력 축에 걸친 "가장 어려운" 801개 프롬프트와 과제별 맞춤 평가 프로그램을 만들었다. 평가 프로그램은 easy-question 게이트 → VLM 증거 grounding(bbox/보조선 반복 확인) → 결정적 Python 채점 순으로 돈다. 최고 T2I(Nano Banana Pro)도 strict 23.9 / relaxed 40.0에 그쳤고, HTML/JS로 그리는 coding model(GPT-6 Astra)이 strict 40.5로 더 높았다.

> 주의: 사용자 메모의 "801 long prompts"는 절반만 맞다. 프롬프트는 평균 199단어 / 254 tokens(중앙값 169단어 / 222 tokens)로 꽤 길다(App. A.1, Fig. 9). 하지만 이 벤치마크는 **어려움을 "양(dose)"이 아니라 "과정(process)"에서 만든다고 명시한다**. 저자 지시문 9번: "More objects, more rows … are a ladder, not a new task". 그러니 긴/밀집 프롬프트에서 생기는 객체 누락을 직접 겨냥한 벤치마크는 아니다.

## 1) 미리 알아야 할 기본 개념

- **분해형 VQA 평가 (TIFA / DSG / GenExam 계열)**: 프롬프트를 원자 질문 여러 개로 쪼개 VLM이 이미지를 보고 답하게 하고, 그 결과를 모아 점수로 만든다. 문제는 "파란 모자가 8개인가?" 같은 질문을 VLM에 한 번에 물으면 자주 틀린다는 점이다. GenOlympiad는 VLM에게 **지각만** 맡기고(박스 그리기, 숫자 읽기) 산술과 판정은 코드로 넘긴다.
- **MLLM-as-judge 편향**: 판정 VLM이 특정 생성 모델 계열과 같은 회사·데이터에서 나왔으면 그 모델의 결과물을 더 잘 "읽어줄" 수 있다. 이 논문의 기본 judge는 **Gemini 2.5 Flash**이고 1위가 **Nano Banana Pro**(Google)다.
- **Easy vs Hard questions**: easy는 전제 조건 확인용이다("주사위가 많은가?", "윗면이 보이는가?"). 하나라도 실패하면 과제 점수를 0으로 처리하는 **게이트**다. hard는 실제 제약("23개인가?", "합이 131인가?")이며 과제당 평균 2.2개, 질문마다 가중치가 다르다.
- **Evidence grounding (help lines)**: hard 질문 중 557/801개가 grounding을 요구한다. 세기 문제는 대상마다 bbox를 그리고, 나침반 문제는 바늘 연장선과 태양 윤곽을 이미지 위에 그린다. 그다음 VLM에게 "선이 제대로 겹쳤나?"를 물어 맞을 때까지 반복한다. 예산을 다 쓰면 실패로 처리한다.
- **Strict vs Relaxed score**: strict는 hard 질문을 *전부* 통과해야 100점, 아니면 0점이다(과제 단위 all-or-nothing). relaxed는 통과한 hard 질문의 가중치 합이다. 그래서 strict는 제약 하나만 놓쳐도 0점이 되어 **누락에 극도로 민감**하다.
- **Withheld (grounding failure)**: grounding이 끝까지 실패하면 과제를 0점으로 매기지 않고 *빼버린다*. 그래서 모델마다 분모가 달라진다.
- **Counterfactual instruction following (C-Fact)**: 상식이나 관습과 반대되는 규칙을 따르게 하는 축이다. 예: 꼴찌 팀이 축하하기, 'N' 바늘이 남쪽을 가리키는 역나침반. 모델의 **prior와 지시가 충돌**할 때 어느 쪽을 따르는지를 측정하므로, "상충 요구 해소" 관심사와 가장 가깝다.
- **Prompt engineering (PE) / rewriting**: LLM이 프롬프트를 다시 써서 T2I 모델에 넘기는 방식이다(PromptEnhancer-32B, GPT-5.6 Sol + Tailored Visions 고정 프롬프트).
- **Partial correlation (축 간)**: 모델 전반 실력의 영향을 선형회귀로 빼낸 잔차끼리 Spearman 상관을 낸다(App. A.1, Fig. 10–11).

## 2) 무엇을 문제로 보았나 (관찰한 증상 · 분석한 원인)

**기존 평가의 문제 (논문 주장)**
- 포화: GenEval은 0.61(2023)에서 약 0.90까지 올랐고 PRISM-Bench는 Nano Banana가 85 이상이다. Arena(Elo)는 비싸고 *어디서 실패하는지* 진단하지 못한다(§1–2). 최근 벤치마크도 빠르게 올라가고 있다. GenExam은 GPT-Image-2 strict 74.6%, MathGen은 Nano Banana Pro 53.7%다.
- VLM에게 직접 물으면 부정확하다. hard 질문을 grounding 없이 물으면 사람과 일치율이 68.4%이고, grounding을 거치면 91.5%다(Table 2, 117문항).

**모델 실패 증상 (수치)**
- 최고 T2I인 Nano Banana Pro도 strict **23.9** / relaxed 40.0이다. GPT-Image-2.5(Sunburst)는 14.9 / 29.6, Seedream 5.0 Pro는 15.1 / 28.4다(Table 1).
- 오픈 모델은 전부 strict 3.5 이하다(FLUX.2 dev 3.5, Qwen-Image 20B 2.2, SD3.5 large 1.3, Sana 1.0–1.4).
- 축별 최저: World(Nano Banana Pro 10.5, GPT-Image-2.5 6.8), Phys(13.1 / 8.1), Spatial(11.2 / 18.4)
- C-Fact: Nano Banana Pro 27.8, GPT-Image-2.5 23.0, Seedream 5.0 Pro 24.1, GPT-Image-2 14.0이다. 저자들의 정성 관찰에 따르면 모델은 "많이 본 나침반"을 그려서 빨간 바늘이 태양 반대쪽을 향하게 하고, "이긴 팀이 축하"하는 장면을 그린다(App. A.4). 즉 **prior override**가 일어난다.

**저자들이 분석한 원인 / 해석**
- coding model이 더 잘하는 이유는 평가가 추론 중심이기 때문이라고 본다. 대신 미감 점수는 낮다(GPT-5.6 Sol 4.61 vs GPT-Image-2.5 5.51, Table 3).
- 오픈 모델은 "경계에서 훈련되지 않았다"고 해석한다. 새 버전이 항상 더 낫지 않다(Fig. 13).
- 축마다 개선 속도가 다르다. 텍스트, 공간, latent는 빠르게 오르고 world knowledge는 느리다(Fig. 7).
- 실패 메커니즘의 정성 분석(App. A.4 negative examples에서 얻은 교훈): 최종 모습을 말로 기술할 수 있는 과제는 LLM이 미리 계산해 프롬프트를 바꿔 쓰면 쉬워지므로 약한 과제다. 또 **LLM이 프롬프트를 단순화할 수 있는 과제**, 예를 들어 "요청됐지만 보이면 안 되는 객체를 빼버리는" 과제도 약하다. 저자들은 이런 과제를 배제했다.

## 3) 방법 (Method)

**과제 = 프롬프트 + 평가 프로그램 (§3.1)**
- 801개 과제, 9개 축(Fig. 3 / Fig. 12의 토픽 분포):
  - Quantitative precision(물체 세기 32, 정밀 측정 22, 공식 기반 판독 22, 계기 판독 11 …)
  - Latent computation(게임 시뮬레이션 37, 다단계 산술 37, 프로그램 실행 18, 스케줄링 17)
  - Physical consistency(빛 20, 액체 13, 하중 13, 유체 13 …)
  - Spatial & 3D(투시 15, 기하 일관성 14 …)
  - Text fidelity(표 합계 24, 단어 퍼즐 23, 텍스트 형식 22, 레이아웃 14)
  - Symbolic systems(기호 인코딩 22, 신호 12, 다이얼 11, 악보 9 …)
  - Long-range consistency(패널 연속성 15, 부품 배치 14, 차트 정확도 12 …)
  - **Counterfactual instruction following(규칙 예외 37, 발명된 규칙 24, 방향 규칙 14, 전역 규칙 변경 11, 조건부 표시 9 → 약 95개)**
  - World-knowledge grounding(천문 19, 표지 표준 19, 전문 지식 12, 실시간 데이터 9 …)
- **구축 절차(App. A.3)**: Claude Opus 5 기반 brainstorming 에이전트가 약 1,600개 과제 설명을 만든다. 사람이 쓴 positive/negative few-shot을 주고 축 정의를 제공하며, 43개 원자 연산자로 이루어진 평가 프레임워크를 쓴다. 이후 저품질 제거와 **난이도 필터**를 거쳐 801개를 얻는다.
  - 난이도 필터: GPT-Image-2, Nano Banana 2, GPT-Image-1.5, FLUX.2 pro, Seedream-4.5 다섯 모델로 생성·채점한다. 남기는 조건은 "최소 2개 모델이 점수를 받고, 만점은 3개 미만, 평균 < 35 또는 (평균 < 60이고 0점 모델이 하나 이상)"이다.
  - 평가 프로그램 역시 Claude Opus 5가 사람의 지시에 따라 작성했다. 검증은 "manual spot checks + AI-based verification"이다(AI Use Statement).
- **에이전트 지시문의 설계 원칙(App. A.4, 요약)**: 정답이 프롬프트에 글자 그대로 나오면 안 된다. 핵심 수치는 감추고 과정에서 어려움을 만든다. VLM은 지각만 하고 산술은 코드가 한다. 한 질문에는 한 사실만 묻는다. 질문에 기대값을 암시하지 않는다. 평가자 실패는 0점이 아니라 withheld로 처리한다. 모든 0점에는 어긴 사실을 이미지 위에 그려서 표시한다.

**평가 파이프라인 (§3.3, Fig. 2, 4, 5)**
1. Easy 질문: Gemini 2.5 Flash yes/no 1회. 사람 일치 94.7%이고, 3회 다수결이어도 95.3%라 1회로 충분하다고 판단했다. 하나라도 fail이면 0점.
2. Hard 질문: 필요하면 반복 grounding(그리기 → VLM 확인 → 재시도)을 거쳐 JSON 상태(bbox 좌표, 읽은 숫자 등)를 만들고 결정적 Python 스크립트로 채점한다.
3. 실패한 grounding은 withheld 처리. 이미지당 평균 VLM 호출은 **59.5회**다(Limitation).

**실험 설정 (§4.1)**
- 폐쇄형: GPT-Image 1/1.5/2/2.5 Sunburst, Nano Banana / Pro / 2, Seedream 4.5 / 5.0 Pro, FLUX.2 pro
- 오픈: FLUX.2 dev/klein 4B·9B, FLUX.1 dev/schnell, SD3.5 L/M, Sana 0.6/1.6/4.8B, Qwen-Image 20B. A100 1장, 텍스트 인코더 context는 최대로 설정(512–1024 tokens, Table 7). context를 넘는 프롬프트는 **생성하지도 채점하지도 않는다**(약 20개 과제).
- Coding model: GPT-6 Astra, GPT-5.6 Sol(medium effort, **웹 검색 가능**). 단일 HTML을 렌더링해 스크린샷을 찍는다(system prompt는 App. A.4).
- 미감: PRISM-Bench 방식, GPT-4.1 판정, 0–10점.

**사람 일치도 검증 (§4.4, Table 2, 4, 6)**
- Prolific 주석자 41명, 질문 365개(easy 131 + hard 234), 이미지는 5개 T2I 모델에서 무작위로 뽑았다. 질문당 3명이 답하고 다수결을 낸 뒤, 그 사람 답을 같은 결정적 채점기에 넣어 비교했다.
- 일치율: 전체 95.3%(348/365), easy 94.7%, hard 95.7%. 혼동행렬(Table 6)은 Human Pass/Auto Fail 13, Human Fail/Auto Pass 4로 **자동 평가가 약간 엄격한 쪽**이다.
- VLM 교체 시 judge 간 일치: Gemini 2.5 Flash–GPT-5.6 96.7%, Gemini–GPT-4.1 96.7%, GPT-5.6–GPT-4.1 97.6%(같은 365문항).

**분석 실험**
- **Prompt rewriting (§4.2)**: GPT-5.6 Sol로 다시 쓰면 GPT-Image-2.5가 strict 14.9 → 33.0, relaxed 29.6 → 48.9로 오른다. 이득은 Latent(6.5 → 55.8)와 Text(30.4 → 62.2)에 집중되어 있고 **Spatial은 오히려 18.4 → 12.5로 하락**했다. PromptEnhancer-32B는 거의 무효(15.1)였다.

- **세대별 향상 (Fig. 7, 13)**: GPT, Seedream, Nano Banana 계열은 새 버전일수록 향상됐다. FLUX, Sana, SD3.5는 축에 따라 새 버전이나 큰 모델이 오히려 하락한다.
- **GPT-Image-2 vs Nano Banana 2 (case study)**: 총점은 비슷하지만 축별 강점이 엇갈린다(Text, Symbol, 3D vs World, Phys, Latent, Long). 저자들은 학습 데이터가 다르기 때문이라고 해석한다.
- **Arena 상관 (Fig. 8)**: relaxed 점수와 AA Arena ρ=0.89(n=15), LMArena 0.82(n=15), Design Arena 0.85(n=11). 예외적으로 Nano Banana Pro는 GenOlympiad에서는 1위인데 Arena에서는 중간이다.
- **재실행 안정성 (Table 5)**: GPT-Image-2.5를 두 번 돌리면 strict 14.9 / 14.2, relaxed 29.6 / 29.3이고, 801개 중 702개 과제가 같은 점수를 받았다. 하지만 축 단위 변동은 크다. Symbol 20.5 → 13.5, Text 30.4 → 25.6, World 6.8 → 11.5.
- **축 간 partial correlation (Fig. 11)**: 대부분 낮거나 음수다. 예: Text–Phys −0.64, C-Fact–Quant −0.60, Spatial–Latent −0.57, C-Fact–World −0.52.

## 5) Challenge를 걸 부분

**(A) 내 비판**
1. **판정자와 1위 모델이 같은 회사다(Google–Google).** easy 질문과 grounding 확인은 Gemini 2.5 Flash가 하고 1위는 Nano Banana Pro다. judge 교체 실험(Table 4)은 *사람 검증용 365문항*에서 질문 단위 일치만 봤다. **전체 801과제를 GPT 계열 judge로 다시 채점해 순위가 유지되는지는 보고하지 않았다.** Gemini가 Google 이미지의 텍스트나 객체를 더 잘 grounding하면 withheld가 줄고 점수가 오르는 경로가 존재한다. withheld는 grounding 실패와 strict 점수가 −0.92로 상관되어 있다는 점까지 고려하면 더 그렇다.
2. **난이도 필터에 따른 선택 편향.** 필터 모델 5개(GPT-Image-2, **Nano Banana 2**, GPT-Image-1.5, FLUX.2 pro, Seedream-4.5)는 정의상 점수가 깎이도록 과제가 골라졌다. 반면 **Nano Banana Pro, GPT-Image-2.5, Seedream 5.0 Pro는 필터에 없다.** 따라서 "Nano Banana Pro 23.9 vs Nano Banana 2 12.4" 같은 격차의 일부는 adversarial filtering의 산물일 수 있다. 저자들도 편향 가능성을 인정하지만(App. A.3) 정량 보정이 없다. 필터에 쓰지 않은 held-out 과제로 재검증해야 한다.
3. **모델마다 분모가 다르다(withheld).** grounding에 실패한 과제를 빼기 때문에 약한 모델은 "가장 망가진" 이미지가 0점이 아니라 분모에서 빠진다. 강한 모델은 어려운 과제까지 채점된다. 같은 과제 집합(교집합)에서 순위를 다시 매겨야 한다. context 초과 과제(약 20개)도 같은 문제를 일으킨다.
4. **프롬프트와 평가 프로그램 모두 LLM(Claude Opus 5)이 썼다.** 검증은 spot check와 AI 검증뿐이다. 사람 검증 365문항은 판정자 일치만 확인하며 *과제 자체가 올바르게 정의됐는지*(정답 유일성, 가중치)는 보지 않는다. 축별 사람 일치도도 없다.
5. **사람 검증 규모와 대표성.** 이미지가 5개 모델에서만 나왔고, 질문 단위 일치만 있으며 과제 단위 strict 판정 일치는 없다. Easy 게이트에서 2–5%의 오판이 생기면 과제 전체가 0점이 되므로 strict에서 오차가 증폭된다.
6. **Strict 점수의 민감도.** hard 질문이 평균 2.2개인 all-or-nothing 구조라 한 질문에서 grounding 오차가 나면 0/100이 갈린다. 축 단위 재실행 변동이 7점(Symbol)이나 되므로 축별 순위 비교는 신뢰하기 어렵다. **샘플은 프롬프트당 1장**이고 seed 분산은 GPT-Image-2.5 하나로만 확인했다.
7. **Coding model 비교의 공정성.** coding model은 웹 검색과 결정적 렌더링을 쓰는 반면 T2I는 픽셀을 생성한다. 이 비교는 "T2I가 열등하다"는 근거보다는 "이 벤치마크가 *기호적 정확성*을 측정한다"는 근거로 읽는 편이 맞다.
8. **PE 결과와 설계 원칙의 긴장.** 저자들은 "LLM이 미리 계산해 다시 쓸 수 있는 과제"를 negative로 배제했다고 했다. 그런데 GPT-5.6 Sol 재작성으로 Latent가 6.5 → 55.8이 된다. 배제가 충분하지 않았거나, T2I의 실패 상당 부분이 생성이 아니라 *해석·계산* 단계라는 뜻이다. 반대로 Spatial은 재작성 후 하락했는데, 재작성이 제약을 *잃어버렸을* 가능성이 있다(아래 아이디어 3).
9. Elo 상관은 n=11–15로 작고, 모델 버전이 시점마다 다를 수 있다.

**(B) 사용자 관심사로 확장할 후속 연구 아이디어**
1. **C-Fact 축으로 "충돌 해소 행동" 분류하기**: C-Fact 약 95과제는 규칙 예외, 역관습, 발명된 규칙처럼 *prior와 지시가 충돌*하는 설정이다. 각 과제의 평가 프로그램에 "prior 기본값이 렌더링됐는가?" 질문을 추가해(예: 바늘이 태양 반대쪽, 승리팀 축하) 실패를 다음과 같이 분류한다.
   - (a) prior override: 관습대로 그림
   - (b) 둘 다 렌더링 / 타협
   - (c) 관련 요소 누락: 축하하는 사람 자체를 빼버림
   - (d) 무관한 실패

   이 분포를 모델과 재작성 여부별로 비교하면 "모델이 상충 요구를 *어떻게* 해소하는가"를 정량화할 수 있다. 기존 평가 프로그램(JSON evidence)을 재사용할 수 있다는 것이 장점이다.
2. **긴 프롬프트 내 제약 위치 효과**: 평균 200단어 프롬프트의 각 hard 질문을 프롬프트 span에 매핑한다(제약 문장이 몇 번째 문장인지). 그리고 "위치 대비 통과율"을 모델별로 회귀한다(축과 질문 유형 통제). 문장 순서를 바꿔도 의미가 보존되는 과제(예: 제약 나열형 "Do not …")를 골라 **순서를 순열한 재생성 실험**을 하면 누락의 위치 의존성을 인과적으로 볼 수 있다.
3. **재작성기가 제약을 잃는지 감사(constraint-preservation audit)**: PE가 Spatial을 떨어뜨린 현상을 분해한다. 재작성된 프롬프트에 원 hard 제약이 텍스트로 남아 있는지 LLM/규칙으로 체크해 "재작성 단계 누락"과 "생성 단계 누락"을 분리한다. 저자들이 negative example에서 지적한 "LLM이 보이면 안 되는 객체를 빼버리는 단순화"도 정량화 대상이다. 이렇게 하면 긴 프롬프트 누락이 *파이프라인의 어느 단계에서* 생기는지 말할 수 있다.
4. **"요청 외 객체" 하위집합 만들기**: 많은 프롬프트에 "nothing else on the table", "Do not add titles/legends", "Only the one central rice grain contains text" 같은 배제 조건이 들어 있다. 이 조건만 따로 hard 질문으로 추출하고 grounding(검출 후 허용 목록 대조)으로 채점하면 *긴 고난도 프롬프트에서 배제 제약이 얼마나 먼저 버려지는가*를 측정할 수 있다.
5. **Judge 편향 통제 재채점**: 같은 801과제를 GPT 계열과 오픈 VLM(Qwen3-VL 등)으로 *전부* 재채점하고, 교집합 과제만으로 순위를 비교한다. 필터 모델 5개와 비필터 모델을 분리한 2×2 분석도 한다. 이 벤치마크를 연구에 인용하거나 재사용하기 전에 해둘 가치가 있는 최소 점검이다.
