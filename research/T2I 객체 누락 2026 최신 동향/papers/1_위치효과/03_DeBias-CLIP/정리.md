- 저자/소속: Marc-Antoine Lavoie (University of Toronto Robotics Institute, Mila 인턴 중 수행), Anas Mahmoud, Aldo Zaimi, Arsène Fansi Tchango (Mila – Quebec AI Institute), Steven L. Waslander (University of Toronto)

- 링크: https://arxiv.org/abs/2602.22419 · 코드 https://github.com/TRAILab/DeBias-CLIP
- 읽은 범위: 본문 전체와 부록(Supplementary A–F, 20쪽) 모두 읽음
- 한 줄 요약: Long-CLIP 계열의 long-caption CLIP은 학습 캡션이 "요약 첫 문장 + 세부 묘사" 구조여서 첫 문장과 앞쪽 토큰에 기대는 shortcut을 배운다. 그래서 short caption 쪽에서 요약 문장을 빼고, 나머지 문장을 무작위로 샘플링하고, 앞쪽에 padding을 넣는 세 가지 caption augmentation을 쓴다. 파라미터는 추가하지 않고 long/short retrieval SOTA를 얻었고 문장 순서 변화에도 더 강하다.

## 1) 미리 알아야 할 기본 개념

- **CLIP text encoder와 77-token 제한**: OpenAI CLIP의 text encoder는 GPT식 **causal mask** Transformer이고, 마지막 층의 **EOT 토큰** hidden state를 projection해 문장 전체 임베딩(pooled embedding)으로 쓴다. 절대 위치 임베딩은 77개뿐이라 그보다 긴 텍스트는 잘린다. 논문에 따르면 77토큰은 대략 3–4문장이다. causal mask 때문에 EOT는 모든 토큰을 볼 수 있지만, 앞쪽 토큰은 뒤쪽 토큰을 보지 못한다.
- **SigLIP / SigLIP2**: softmax contrastive loss를 pairwise sigmoid loss로 바꾼 CLIP 변형이다. text encoder에 causal mask가 **없고** context는 64토큰이다. 논문 결과로는 SigLIP 계열이 오히려 위치 편향이 더 심하다(Fig. 2, 3). 그래서 편향이 causal mask 탓만은 아니라는 증거로 쓰인다.
- **Long-CLIP (ECCV'24)**: 사전학습된 CLIP의 위치 임베딩 중 **앞 20개는 고정**하고 나머지는 선형보간으로 **4배 늘려** 77→248토큰으로 확장한다. 그다음 ShareGPT4V(1.2M장, GPT-4V류 long caption)로 fine-tune한다. 손실은 두 가지다. (i) long caption ↔ 이미지 전체 feature, (ii) **첫 문장(=short caption) ↔ 이미지 feature의 PCA 저차원 근사 f(v)**. (ii)는 short-text 성능을 지키려는 장치다.
- **Summary-first caption 구조**: ShareGPT4V, Urban1k, DCI, DOCCI 같은 long-caption 데이터셋은 모두 "한 문장 요약 + 세부 묘사" 형식이다(Table 1). 사람 캡션이든 LLM 캡션이든 같다. 논문의 핵심 관찰 대상이 이 구조다.
- **Text-to-image / image-to-text retrieval (T2I/I2T top-1)**: T2I는 캡션으로 이미지를, I2T는 이미지로 캡션을 찾는 과제다. 이 논문에서 T2I는 생성이 아니라 **retrieval 방향**을 뜻한다. 이미지 생성 실험은 부록 F의 SDXL 실험 하나뿐이다.
- **Keep / Move / Remove / Swap 2 / First only**: 위치 민감도를 재는 텍스트 섭동이다. Keep은 원문, Move는 1번과 4번 문장 교환(Move 2는 1↔2, Move 4는 1↔4), Remove는 첫 문장 삭제, Swap 2는 앞 두 문장만 남기고 순서를 바꾼 것, First only는 첫 문장만 쓴 것이다.
- **Pre-softmax attention 분석**: 마지막 층에서 출력 토큰(EOT)의 query와 각 위치 key의 내적 q_EOT·K^T를 위치별로 평균한 값이다. padding이 아닌 경우만 세도록 정규화한다. 출력 표현이 어느 위치의 정보를 끌어오는지 보여 주는 지표다(Fig. 1b, 부록 E.3).

## 2) 무엇을 문제로 보았나

### 관찰한 증상
- **Early-token bias (Sec. 3.2.1, Fig. 2, 7)**: DOCCI 캡션의 앞 두 문장(평균 46.6토큰, 컨텍스트 한도 안)만 남기고 앞에 의미 없는 문장 "This is a photo."를 1–5개 붙였다. 정보는 그대로인데 retrieval이 CLIP, OpenCLIP, SigLIP, SigLIP2 모두에서 떨어진다. SigLIP 계열은 padding 1–2문장만 붙여도 크게 떨어진다. 정확한 수치는 그래프로만 제시되어 있고, y축 범위는 대략 0.50–0.70이다.
- **문장 순서 민감도 (Sec. 3.2.2, Fig. 3)**: 앞 두 문장의 순서를 바꾸면(Swap 2) 네 모델 모두 성능이 떨어진다. SigLIP2가 **−8.5%**로 가장 크게 떨어진다. SigLIP 계열에서는 두 번째 문장이 주는 추가 정보의 이득이 순서만 바뀌어도 사라진다.
- **Long-CLIP도 편향을 물려받음 (Sec. 3.3, Fig. 1a)**: DOCCI T2I retrieval에서 Move는 **−9.7%**, Remove는 **−17.1%**다.
- **Attention 감쇠 (Fig. 1b, 11)**: Long-CLIP은 EOT→토큰 attention이 앞쪽에서 가장 크고, 10번째 위치 이후로 꾸준히 줄어든다. SmartCLIP도 50토큰 이후로 줄어든다.
- **요약 문장이 shortcut이라는 정량 증거 (Sec. 4.2)**: Long-CLIP으로 DOCCI positive pair의 유사도를 쟀더니 **요약 문장 하나만 쓴 경우 0.320 > 전체 캡션 0.308**이었다. 정보를 더 넣었는데 정렬이 오히려 나빠진다.

### 원인 분석 (저자 주장)
1. 사전학습 CLIP은 짧은 캡션이 지배적인 데이터로 학습되어 앞쪽 토큰과 핵심 객체 중심으로 정렬되어 있다. 유효 context window도 짧다.
2. long-caption fine-tuning 데이터가 **summary-first** 형식이라, 첫 문장만으로도 contrastive loss를 충분히 낮출 수 있다. 그래서 뒤쪽 토큰을 쓰도록 학습할 압력이 약하다. 이것이 shortcut이다.
3. Long-CLIP의 short-caption loss는 첫 문장을 그대로 short caption으로 써서 이 shortcut을 오히려 강화한다.
4. 아키텍처 탓만은 아니라는 근거(부록 E.2):
   - RoPE를 쓰는 TULIP도 Move −7.3%, Remove −16.1%로 편향이 남는다.
   - EOT 대신 **token average pooling**으로 바꿔도 편향이 풀리지 않는다. Long-CLIP 원본은 Move −10.4%, avg pooling 버전은 −11.0%다.
   - 비-causal인 SigLIP도 편향이 있다.
   - 저자들은 이를 근거로 원인이 **데이터 구조**에 있다고 본다.
5. 부록 E.3(Fig. 12)에서는 위치 편향과 요약 문장 편향을 분리해 본다. Move 4 조건에서도 (i) 앞 위치의 attention이 여전히 크고, (ii) 뒤로 옮긴 요약 문장(50–100번 위치)이 원래보다 약 +0.2 높은 attention을 받는다. 즉 **위치 편향과 정보밀도(요약) 편향이 함께 존재**한다.
   - 추가로, SOT 토큰의 pre-softmax 값은 약 2.5이고 softmax 확률로는 0.35–0.40이다. SOT가 attention sink 역할을 하는 것으로 보인다.

## 3) 방법 (Method)

Long-CLIP 학습 틀은 그대로 두고 **short caption 쪽 입력만** 바꾼다(Sec. 4, Table 2, Algorithm 1).

1. **요약 문장 제거 (Sec. 4.2)**: short caption을 첫 문장 s1 대신 C^no_sum = [s2,…,sk]로 바꾼다. long caption C^ℓ = [s1,…,sk]는 그대로 학습에 쓴다.
2. **문장 sub-sampling (Sec. 4.3)**: n_samp ~ U{1,…,k−1}개를 비복원으로 뽑는다. **순서는 보존하지 않는다**(예: [s4, s2]). LLM rewriting보다 비용이 거의 들지 않는 변형이다.
3. **Prefix token padding (Sec. 4.4)**: 뒤쪽 padding 개수 n_post 가운데 n_pre ~ U{0,…,n_post}개를 SOT **바로 뒤**로 옮긴다. 결과는 [SOT, PAD×n_pre, s4, s2, EOT, PAD×(n_post−n_pre)]다. 텍스트를 자르지 않고 짧은 캡션을 뒤쪽 위치로 밀어, 뒤쪽 위치 임베딩도 학습되게 한다.
   - 저자들의 해석: 이렇게 하면 앞쪽 위치는 주로 long caption(요약 문장)으로 학습되고, short-text 성능도 함께 지켜진다.
4. **손실**: L = λs·Ls(u^s, f(v)) + (1−λs)·Lℓ(u^ℓ, v). Fig. 5 기준으로 λs = 0.1일 때 short/long trade-off가 가장 좋고, long은 0.25에서 최고다. 0.25를 넘으면 둘 다 나빠진다.
- **학습 설정 (Table 6)**:
  - 248토큰, 앞 20개 위치 임베딩 고정 후 ×4 보간
  - ShareGPT4V로 3 epoch, batch 256, AdamW, lr 1e-6, wd 1e-2, warm-up 200 iter
  - A100 4장
  - **추가 파라미터 0개**, 추론 비용 변화 없음 (drop-in replacement)
- 비교 대상 설계: SmartCLIP은 요약 문장부터 시작하는 연속 문장 truncation을 쓰고, FineLIP은 추론 시 cross-modal refinement 모듈이 필요하다. DeBias-CLIP은 순수 data augmentation이다.

### 이미지 생성 (부록 F, Table 12, Fig. 15)
- SDXL의 CLIP text encoder를 Long-CLIP 또는 DeBias-CLIP으로 바꿔서 ShareGPT4V validation의 long caption 1000개로 이미지를 생성했다.
- 결과는 "FID" **0.335 → 0.317**, DINO score **0.515 → 0.528**이다.
- 정성 관찰:
  - DeBias는 뒤 문장의 세부(녹색 신호등, 일본어 간판)를 더 잘 반영한다.
  - 저자 스스로 **모든 CLIP 계열이 관계 이해에 약하다**고 명시한다. 좌우 위치, 개수, 속성-객체 결합이 약하다.
  - 예: "주황 공룡이 파란 칫솔을 문다"가 "파란 공룡"으로 섞이는 attribute leakage가 생긴다.

## 5) Challenge를 걸 부분

### 가정과 해석의 약점
- **Remove 실험은 위치 효과와 정보 손실을 섞어서 잰다.** 요약 문장을 지우면 정보도 사라진다. 위치 효과만 따로 재려면 Move나 neutral padding(Fig. 2) 쪽이 깨끗하다. "Remove 강건성 향상"은 위치 편향 감소보다 "세부 문장만으로 매칭하는 능력 향상"에 가깝다.
- **"Shortcut" 주장의 인과 근거가 간접적이다.** 유사도 0.320 대 0.308과 ablation 결과는 상관 증거다. summary-first가 아닌 데이터(예: 순서를 섞은 caption이나 요약이 끝에 오는 caption)로 Long-CLIP을 학습해 보는 통제 실험은 Tab. 9의 Shuffle 변형(short caption만 해당)을 빼면 없다.
- **개선이 사실상 한 가지 요소에서 나온다.** Table 5에서 long 성능 향상은 "No summary"가 거의 전부이고, padding은 DOCCI를 오히려 낮춘다(80.9→79.7). 세 augmentation이 모두 필요하다는 서사는 short-text 쪽 ~1%p 향상에 기대고 있다.
- **attention 감쇠가 성능 원인인지는 보이지 않았다.** Fig. 1b와 Fig. 11은 평균 attention logit이 평탄해졌다는 관찰일 뿐, 그것이 retrieval 향상의 원인이라는 개입 실험(attention 조작)은 없다.

### 실험 설계·통계
- seed 반복, 분산, 신뢰구간이 **전혀 없다.** short-text에서 SmartCLIP과의 차이(±0.5–1%p)는 유의하다고 말하기 어렵다.
- 비교 수치 일부는 원 논문에서 가져오고 일부는 직접 재현해, epoch과 batch가 다르다. Long-CLIP은 1 epoch/batch 1024이고 DeBias는 3 epoch/batch 256이다. 저자들은 Tab. 8에서 같은 1 epoch 비교를 보여 일부 보완했다.
- 저자도 인정한 한계: **평가 벤치마크 자체가 summary-first 구조**라 위치 편향이 가려진다. 문서 페이지처럼 실제 long-context retrieval 벤치마크가 필요하다고 말한다.

### T2I 생성 관점의 한계 (저자가 말하지 않은 부분)
- **생성 평가가 매우 빈약하다.**
  - 이미지 1000장으로 FID·DINO 두 지표만 쟀다. FID 값이 0.3대인 것은 통상 FID 스케일(수십)과 맞지 않아, 정규화된 다른 거리일 수 있다(정의 불명).
  - 객체 recall, VQA 기반 지표, 위치별 누락률 같은 **"뒤쪽 객체가 실제로 덜 빠지는가"를 직접 잰 수치가 없다.**
- **SDXL 통합 방식이 불명확하다.**
  - SDXL은 CLIP ViT-L과 OpenCLIP bigG 두 encoder의 per-token hidden state와 bigG pooled 벡터를 쓰고, 77토큰으로 학습되었다.
  - 248토큰 출력을 UNet에 어떻게 넣었는지, bigG 쪽은 어떻게 처리했는지, UNet을 다시 학습했는지 서술이 없다.
  - DeBias-CLIP은 **pooled EOT 표현**을 고친 것이라, UNet cross-attention이 쓰는 per-token hidden state에도 같은 개선이 일어나는지는 별개 문제다.
- **최신 MM-DiT 계열과의 관련성이 제한적이다.** SD3, FLUX, Qwen-Image 등은 T5나 LLM의 per-token 임베딩을 주 조건으로 쓰고, CLIP은 pooled 벡터(전역 modulation)로만 쓰거나 아예 쓰지 않는다. 따라서 "CLIP early-token bias가 긴 프롬프트 객체 누락의 원인"이라는 가설은 이 논문만으로는 최신 모델에 바로 연결되지 않는다.
- 문장 순서를 보존하지 않는 sampling은 문장 간 상호참조("It", "the latter")를 깨뜨린다. 관계와 공참조 표현에 미치는 영향은 평가되지 않았다.

### 사용자 관심사로 확장할 후속 연구 아이디어
1. **"Neutral filler / 문장 이동"으로 T2I 위치별 누락 곡선 측정**
   - Fig. 2의 "This is a photo." prepend와 Move 프로토콜을 생성 모델에 그대로 옮긴다.
   - 같은 객체 집합을 문장 순서만 바꿔 여러 번 생성하고, 객체별 VQA/detector recall을 **언급 위치의 함수**로 그린다.
   - SD3와 FLUX.1에서 **CLIP pooled 벡터를 0이나 평균으로 ablation**하거나 DeBias-CLIP pooled로 교체한다. 그러면 누락의 위치 의존성이 pooled CLIP 경로에서 오는지 T5/LLM per-token 경로에서 오는지 분리할 수 있다.
2. **T2I 학습 캡션의 summary-first 구조가 뒤쪽 객체 누락을 낳는가?**
   - 최근 T2I는 LLM recaption(summary-first)으로 학습된다.
   - DeBias식 augmentation(요약 제거, 문장 셔플·sub-sample, prefix padding)을 T2I fine-tuning(LoRA 수준)에 적용한다. 그다음 DPG-Bench, DSG, T2I-CompBench의 long prompt에서 **문장 위치별 객체 recall**이 평탄해지는지 확인한다. 데이터 쪽 원인에 대한 인과 검증이 된다.
3. **상충 요구에서의 위치 우선순위**
   - 요약 문장과 세부 문장이 충돌하는 프롬프트를 만든다. 예: 1문장 "A photo of a cat on a sofa." / 4문장 "There are two dogs on the sofa, and no cat."
   - 어느 쪽이 이기는지를 위치(앞/뒤)와 정보 유형(요약/세부)을 교차 설계해서 측정한다.
   - Fig. 12가 보여 준 "위치 편향 + 요약 편향" 두 요인이 생성 모델의 conflict resolution에서도 나타나는지 보는 실험이다.
4. **요청 외 객체(unrequested objects)의 출처로서 요약 문장**
   - "a serene moment at a zoo" 같은 요약 표현이 장면 prior를 불러와, 언급되지 않은 객체(동물, 펜스, 관람객)를 생성하게 하는지 본다.
   - 요약 문장 유무와 위치를 조작해 hallucinated object rate를 재고, DeBias-CLIP과 Long-CLIP을 비교한다.
5. **Attention sink(SOT)와 누락**
   - SOT가 softmax 질량의 35–40%를 가져간다는 관찰(E.3)을 MM-DiT joint attention으로 확장한다. text 쪽 sink 토큰이 뒤쪽 객체 토큰의 image→text attention 질량을 빼앗는지 측정한다.
   - sink를 재분배하는 training-free 개입이 누락을 줄이는지도 함께 본다.
